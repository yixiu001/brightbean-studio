# 开源社交媒体管理平台 - 功能规范 v2

## 产品定位

专为机构和中小企业构建的开源、自托管社交媒体管理平台。云托管版本和自托管版本是相同的 - 每个功能都是永久免费的，没有每个席位、每个频道或每个工作空间的限制。货币化完全来自可选的付费支持计划和咨询，而不是来自功能门控。

**核心承诺：** Everything Sendible、SocialPilot 和 ContentStudio 每月收费 100-300 美元 - 完全免费，无论是云托管还是自托管。

**支持的平台：** Facebook Pages、Instagram（帖子、卷轴、故事、轮播）、LinkedIn（个人资料 + 公司页面）、TikTok、YouTube（视频 + 短片）、Pinterest、Threads、Bluesky、Google Business Profile、Mastodon。

**不支持：** X/Twitter 已明确排除在平台之外。

**集成架构：** 所有平台集成均直接使用官方第一方API。未使用统一的社交媒体 API 提供商（Ayrshare、Outstand 等）。用户提供自己的平台 API 凭据以进行自托管部署。云版本在平台条款允许的情况下管理共享应用程序凭据。

# 1. ORGANIZATION & WORKSPACE MANAGEMENT

---

## F-1.1 - 组织管理

### 目的
组织是代表机构、公司或个人用户的顶级实体。它包含所有工作区、成员、设置和 API 凭据。每个用户都属于一个组织（多组织支持超出了 v1 的范围）。

### 用户故事
- 作为新用户，我注册后会自动为我创建一个组织 - 在开始工作之前我不需要配置任何内容。
- 作为组织所有者，我可以随时从设置中重命名我的组织、更新其徽标并配置组织范围的设置。
- 作为组织所有者，我可以删除我的组织，这会在确认期后永久删除所有数据。

### 功能要求

**创作：**
- 当用户注册（电子邮件/密码或 OAuth）时，系统会在后台自动创建一个组织，并且零用户输入。没有入门向导，没有名称提示，没有徽标上传 - 用户直接登陆一个空的仪表板，准备创建他们的第一个工作区。
- 自动创建的组织使用合理的默认值：名称设置为用户名+“组织”（例如“Jan's Organization”），无徽标，时区默认为用户浏览器检测到的时区。
- 注册的用户将被自动分配为所有者角色。
- 所有默认设置（名称、徽标、时区、品牌）都可以随时从组织设置（可通过侧边栏 → 设置 → 组织访问）进行更改。
- 每次注册都会创建一个组织。 v1 中没有多组织切换。
- 如果用户被邀请加入现有组织（通过 F-1.3 邀请流程），则不会创建新组织 - 他们会加入现有组织。

**设置（所有者和管理员角色可以访问）：**
- 组织名称（字符串，2–100 个字符）。
- 组织徽标（图像上传，用于侧边栏、报告、白标签）。接受 PNG、JPG、SVG。最大 2MB。存储在媒体存储后端。
- 默认时区（用作未设置自己的工作区的后备时区）。
- 平台 API 凭据（请参阅 F-1.5）。

**删除：**
- 只有所有者才能发起删除。
- 删除过程分为两步：(1) 所有者单击“删除组织”，(2) 系统发送一封带有唯一链接的确认电子邮件，该链接将在 24 小时内过期，(3) 单击该链接会在 7 天宽限期后安排删除。
- 宽限期过后，所有数据将被永久删除：工作区、帖子、媒体、分析、成员、OAuth 令牌。
- 当删除开始和完成时，系统会向所有管理员发送电子邮件通知。

**删除取消（宽限期内）：**
- 在 7 天的宽限期内，所有者可以随时取消计划的删除。
- 可以从两个地方取消：(1) 应用程序中每个页面顶部的显着横幅，上面写着“您的组织计划于 [日期] 删除。要取消删除吗？”带有“取消删除”按钮，以及 (2) 删除确认电子邮件中的链接，上面写着“改变主意？取消删除”。
- 单击“取消删除”会立即将组织恢复到正常状态 - 软删除时间戳被清除，横幅消失，所有功能都恢复。
- 取消不需要电子邮件重新确认 - 单击按钮就足够了，因为用户已经被验证为所有者。
- 取消后，所有者可以随时重新启动删除，从而重新启动完整的两步流程和新的 7 天宽限期。
- 如果宽限期到期而没有取消，则删除是不可逆转的。

### 数据模型
- `Organization`：id、name、logo_url、default_timezone、created_at、updated_at、deletion_requested_at（日期时间、可为空 - 确认删除时设置）、deletion_scheduled_for（日期时间、可为空 - 删除_请求_at + 7 天）、deleted_at（日期时间、可为空 - 在宽限期后执行删除时设置）。

### 依赖关系
- F-1.3（成员和角色）- 用于基于角色的设置访问。
- F-5.2（白标）- 徽标重复用于白标品牌。
- F-1.5（平台 API 凭据）- 存储在组织级别。

### 验收标准
- 新用户可以在 10 秒内注册并登录到完全创建的组织的空仪表板上 - 没有任何入职步骤、表单或向导会阻止他们。
- 自动创建的组织有一个合理的默认名称，该名称源自用户名和与其浏览器匹配的时区。
- 稍后在设置中进行的组织名称和徽标更改会立即反映在所有视图（侧边栏、报告、白标签门户）中。
- 组织删除会在 30 秒内发送确认电子邮件。所有者可以在 7 天宽限期内随时取消删除。宽限期结束后，所有数据将被永久删除，且不会取消。
- 删除后不保留任何孤立数据（通过清理审核作业验证）。

## F-1.2 - 工作区管理

### 目的
工作区是一个客户或品牌的隔离环境。所有内容、社交帐户、媒体、分析和收件箱消息都限定在工作区范围内。工作区之间不会发生数据泄漏。代理机构为每个客户创建一个工作区。

### 用户故事
- 作为代理经理，我可以为我加入的每个客户创建一个新的工作区。
- 作为工作区所有者，我可以配置工作区特定的设置（时区、品牌颜色、默认主题标签）。
- 作为代理管理员，我可以在客户流失时存档工作区，而不会丢失历史数据。
- 作为团队成员，我只能看到我被邀请加入的工作区。

### 功能要求

**创作：**
- 任何组织管理员或所有者都可以创建工作区。
- 必填字段：工作区名称（2–100 个字符）。
- 可选字段：工作区图标/头像（图像，最大 1MB）、时区（默认为组织时区）、描述（文本，最多 500 个字符）。
- 创建者会自动添加为工作区所有者。

**设置（工作区所有者和管理员可访问）：**
- 名称、图标、描述、时区。
- 品牌颜色：主色（十六进制）、次要颜色（十六进制）。用于报告和客户端门户。
- 默认主题标签：在该工作区的编辑器中自动建议的一组主题标签。存储为字符串列表。
- 默认第一条评论模板：自动填充编辑器中第一条评论字段的文本。
- 审批工作流程模式：无、可选、required_internal、required_internal_and_client（请参阅 F-2.2）。

**工作区切换器：**
- 侧边栏显示当前用户有权访问的所有工作区的列表，并通过搜索/过滤器输入按字母顺序排序。
- 单击工作区会加载其上下文：日历、收件箱、分析、媒体库所有范围都适用于该工作区。
- “固定”选项允许用户将常用工作区固定到列表顶部。
- 上次使用的工作区会被记住并在下次登录时加载。

**存档：**
- 工作区所有者或组织管理员可以存档工作区。
- 默认情况下，已存档的工作区在侧边栏中隐藏，但可通过工作区设置中的“显示已存档”切换进行访问。
- 所有数据均被保留。存档工作区中的预定帖子已暂停（未删除）。发布被禁用。
- 存档的工作空间可以随时取消存档，恢复全部功能。

**删除：**
- 只有组织所有者或组织管理员才能永久删除工作区。
- 删除确认需要输入工作区名称。
- 删除是立即且永久的。所有工作区数据（帖子、媒体、分析、收件箱消息、社交帐户连接）都将被删除。
- 连接的社交帐户已断开连接（OAuth 令牌在平台支持的情况下被撤销）。

**跨工作空间视图（组织仪表板）：**
- 组织管理员和所有者可以访问组织级仪表板，该仪表板跨工作区聚合数据。
- 可用视图：“所有待批准的帖子”（所有工作区等待批准的帖子队列）、“所有计划的帖子”（所有工作区的日历视图，按工作区进行颜色编码）、“所有失败的帖子”（未能在所有工作区发布的帖子）。
- 此仪表板是只读的 - 操作（批准、编辑、重试）需要导航到特定工作区。

### 数据模型
- `Workspace`：id、organization_id、名称、icon_url、描述、时区、primary_color、 secondary_color、default_hashtags（json 数组）、default_first_comment、approval_workflow_mode（枚举）、is_archived（布尔值）、created_at、updated_at。

### 依赖关系
- F-1.1（组织）- 工作区属于组织。
- F-1.3（成员和角色）- 工作区级别角色分配。
- F-2.2（审批工作流程）- 每个工作区配置工作流程模式。

### 验收标准
- 只需在仪表板上单击不到 3 次即可创建工作区。
- 切换工作空间会在 1 秒内加载新工作空间的数据（感知）。
- 归档工作区会立即对非管理员用户隐藏它并暂停所有计划的帖子。
- 删除工作区会删除所有关联数据；没有外键违规或孤立记录。
- 对于拥有最多 50 个工作区的组织，跨工作区仪表板可在 3 秒内加载。

## F-1.3 - 成员和基于角色的访问控制 (RBAC)

### 目的
在组织级别和工作区级别控制谁可以做什么。两层 RBAC 确保代理机构可以准确地为团队成员和客户提供他们所需的访问权限。

### 用户故事
- 作为组织所有者，我可以通过电子邮件邀请团队成员加入我的组织。
- 作为组织管理员，我可以将成员分配到具有特定角色的特定工作区。
- 作为工作区经理，我可以使用客户角色邀请客户到我的工作区，以便他们可以批准帖子。
- 作为贡献者，我可以创建草稿帖子，但不能发布或批准任何内容。
- 作为组织管理员，我可以创建具有特定权限切换的自定义角色。

### 功能要求

**组织角色（管理组织级别的行动）：**

| 角色 | 管理成员 | 创建/删除工作区 | 查看所有工作区 | 配置白标| 管理 API 凭据 | 删除组织 |
|------|---------------|------------------------|--------------------|--------------------|----------------------|-------------------|
| 所有者 | 是 | 是 | 是 | 是| 是 | 是 |
| 管理员 | 是 | 是 | 是 | 是| 是 | 否 |
| 成员 | 否 | 否 | 已分配 | 否| 否 | 否 |

- 每个组织只有一个所有者。所有权可以转让给另一位管理员（双方进行两步确认和电子邮件验证）。
- 管理员可以邀请新成员、更改成员角色（所有者除外）以及删除成员。
- 成员没有组织级别的管理权力；他们只与分配给他们的工作区交互。

**工作区角色（管理工作区级别的操作）：**

| 角色 | 创建帖子 | 编辑自己的帖子 | 编辑他人的帖子 | 批准帖子| 直接发布 | 管理社交帐户 | 查看分析 | 使用收件箱 | 从收件箱回复| 管理工作区设置 |
|------|-------------|---------------|-------------------|--------------|-----------------|----------------------|---------------|-----------|-----------------|-------------------------|
| 所有者 | 是 | 是 | 是 | 是| 是 | 是 | 是 | 是 | 是| 是 |
| 经理 | 是 | 是 | 是 | 是| 是 | 是 | 是 | 是 | 是| 否 |
| 编辑器 | 是 | 是 | 是 | 否| 可配置 | 否 | 是 | 是 | 是| 否 |
| 贡献者 | 是（仅限草稿） | 是（自己的草稿） | 否 | 否| 无 | 无 | 有限 | 无 | 无| 否 |
| 客户端 | 否 | 否 | 否 | 是| 无 | 无 | 仅查看 | 无 | 无| 否 |
| 查看器 | 否 | 否 | 否 | 否| 无 | 无 | 仅查看 | 无 | 无| 否 |

- 编辑者直接发布的“可配置”意味着：工作区所有者可以切换编辑者是否可以绕过审批工作流程并直接安排/发布。
- 贡献者的“有限”分析意味着：只能查看自己帖子的参与度指标。

**自定义角色：**
- 组织管理员可以通过命名自定义工作区角色并单独切换每个权限来创建自定义工作区角色。
- 自定义角色可在组织中的所有工作区中使用。
- 内置角色（所有者、管理者、编辑者、贡献者、客户、查看者）无法修改或删除。

**邀请流程：**
- 组织管理员/所有者通过电子邮件地址邀请用户。
- 系统发送一封带有注册/登录链接的邀请电子邮件。
- 如果受邀者已在组织中拥有帐户，则直接添加。
- 如果被邀请者是新的，他们会创建一个帐户并自动添加到组织中。
- 邀请指定：将它们添加到哪个 workspace(s)，以及每个的工作空间角色。
- 邀请将在 7 天后过期。管理员可以重新发送或撤销待处理的邀请。
- 待处理的邀请在组织成员设置的“待处理的邀请”列表中可见。

**客户邀请函（特殊流程）：**
- 当邀请具有客户角色的人员时，邀请电子邮件使用简化的入职流程。
- 客户可以选择通过 magic link 访问平台（无需密码） - 请参阅 F-1.4。
- 客户帐户被标记为外部帐户，并且默认情况下从内部团队成员列表中隐藏（切换以显示）。

**会员删除：**
- 组织管理员可以从组织中完全删除成员（从所有工作区中删除）。
- 工作区所有者/经理只能从其特定工作区中删除成员。
- 删除成员不会删除其创作的内容（帖子、评论）。作者身份被保留为显示名称。
- 如果已删除的成员是工作区的唯一管理员，则删除将被阻止，直到指定另一个管理员为止。

### 数据模型
- `User`：id、电子邮件、姓名、avatar_url、password_hash、created_at。
- `OrgMembership`：id、user_id、organization_id、org_role（枚举：所有者、管理员、成员）、invited_at、accepted_at。
- `WorkspaceMembership`：id、user_id、workspace_id、workspace_role（枚举或 CustomRole 的外键）、added_at。
- `CustomRole`：id、organization_id、名称、权限（将权限键映射到布尔值的 json 对象）。
- `Invitation`：id、organization_id、电子邮件、workspace_assignments（json：[{workspace_id, role}]）、invited_by、token、expires_at、accepted_at。

### 验收标准
- 仅具有贡献者角色的用户可以创建草稿，但如果他们尝试计划、发布或批准，则会收到“权限被拒绝”错误。
- 客户端角色用户只能看到：其工作区的批准队列、已发布的后期分析和报告下载。没有侧边栏导航到日历、作曲家、收件箱或设置。
- 自定义角色正确应用每个权限切换；更改自定义角色的权限会立即对分配该角色的所有用户生效。
- 删除工作区的最后一个管理器被阻止，并显示明确的错误消息。
- 邀请电子邮件在发送后 60 秒内到达。

## F-1.4 - 客户端

### 目的
为客户提供最小化的品牌界面来审查和批准内容并查看绩效报告 - 无需他们了解完整的平台或查看其他客户的数据。

### 用户故事
- 作为代理经理，我可以向我的客户发送一个神奇的链接来查看本周的预定帖子。
- 作为客户，我可以通过评论解释我的反馈来批准或拒绝帖子。
- 作为客户，我可以查看我的品牌已发布的帖子分析。
- 作为客户，我可以下载我的机构与我共享的报告。
- 作为客户，我不需要创建密码或记住登录凭据。

### 功能要求

**访问方法：**
- **魔法链接（主要）：** 通过电子邮件发送的独特、限时的 URL。单击它会自动登录客户端。无需密码。魔术链接将在 30 天后过期，但工作区管理器可以随时重新生成。
- **电子邮件 + 密码（可选）：** 客户可以选择在入职期间设置密码以实现持久访问。登录密码仅显示workspace(s)。
- Magic 链接 URL 包含加密安全令牌（最小 32 字节，URL 安全 base64 编码）。令牌在初始登录时是一次性使用的，但会创建持续 30 天的会话。

**门户网站浏览量：**

*批准队列：*
- 客户工作区中状态为“pending_client”的所有帖子的列表。
- 每篇帖子显示：预定日期/时间、目标 platform(s)、标题文本、附加媒体（图像内联渲染、视频显示带有播放按钮的缩略图）、作者姓名。
- 客户可以单击帖子将其展开为详细视图，显示完整的特定于平台的预览（它在 Instagram、LinkedIn 等上的外观）。
- 每个帖子的操作：“批准”（绿色按钮）、“请求更改”（橙色按钮，需要评论）、“拒绝”（红色按钮，需要评论）。
- 批量操作：选择多个帖子并一次性批准所有帖子。
- 客户已审阅的帖子会显示“已审阅”徽章以及他们的操作和评论。

*发布内容：*
- 客户工作区已发布帖子的时间列表。
- 每篇帖子显示：发布日期、平台、标题片段、参与摘要（点赞、评论、分享、覆盖范围 - 仅数字，无图表）。
- 单击帖子将打开包含完整参与度指标的详细视图。

*报告：*
- 与此工作区共享的报告列表（通过 F-4.3 生成）。
- 每个报告显示：标题、日期范围、生成日期。
- 操作：在浏览器中查看（呈现为 8800000000000000888），下载为 PDF。
- 可共享的报告链接 (F-4.3) 也会在此门户视图中呈现。

*活动日志：*
- 客户已采取的行动的时间列表：批准、拒绝、评论。
- 只读。帮助客户跟踪他们已经评论过的内容。

**品牌：**
- 如果通过 F-5.2 配置，门户将显示机构的白标品牌（徽标、颜色、自定义域）。
- 如果未配置白标签，门户将显示平台的默认品牌。
- 如果白标签处于活动状态，则平台名称对客户端永远不可见。

**限制：**
- 客户无法：创建或编辑帖子、更改时间表、访问作曲家、访问完整日历、访问社交收件箱、访问媒体库、查看内部团队评论、访问其他工作区、访问组织设置。
- 客户可以查看帖子的外部评论（团队标记为“客户可见”的评论）。

**通知：**
- 当帖子提交给客户批准时，客户会收到一封电子邮件，其中包含指向批准队列的神奇链接。
- 电子邮件主题行可按工作区进行配置（默认值：“[工作区名称] - 帖子可供您审阅”）。
- 电子邮件正文显示待处理帖子的数量和“立即查看”按钮（神奇链接）。
- 如果帖子在可配置的小时数（默认值：48 小时）内保持待处理状态，则会发送提醒电子邮件。每个后期批次最多 2 次提醒。

### 数据模型
- `MagicLinkToken`：id、user_id、workspace_id、令牌（字符串、唯一、索引）、created_at、expires_at、last_used_at。
- 会话管理：标准会话 cookie，在 Magic Link 身份验证后有 30 天的有效期。
- 客户端门户页面是按workspace_id 和workspace_role =“client”过滤的服务器渲染视图。

### 依赖关系
- F-1.3 (RBAC) - 客户端角色权限。
- F-2.2（批准工作流程）- 批准/拒绝后操作。
- F-4.3（报告生成器）- 门户中可见的报告。
- F-5.2（白标）- 应用于门户的品牌。
- F-7.1（通知系统）- 通过电子邮件发送神奇链接和提醒。

### 验收标准
- 客户可以在 15 秒内从收到电子邮件到查看他们的第一篇帖子（单击神奇链接 → 门户加载 → 批准队列可见）。
- 批准帖子会在 1 秒内将帖子状态更新为“已批准”，并触发向工作区团队发送通知。
- 门户在移动设备上正确呈现（响应式设计，最小 320 像素视口宽度）。
- 如果配置了白标签，则门户 UI 或电子邮件中的任何位置都会出现对平台自有品牌的零引用。
- Magic Link 代币过期后无法重复使用；尝试使用过期的令牌会重定向到“请求新链接”页面。

## F-1.5 - 平台 API 凭证管理

### 目的
管理连接到每个社交媒体平台的官方 API 所需的 API 凭据（应用程序 ID、应用程序密钥、回调 URL）。对于自托管部署，用户必须提供自己的开发人员应用程序凭据。对于云版本，共享应用程序凭据由平台运营商管理。

### 用户故事
- 作为自托管管理员，我可以输入我的 Facebook 应用程序 ID 和密钥，以便我的实例可以连接到 Facebook Graph API。
- 作为自托管管理员，我可以查看配置了哪些平台以及缺少凭据。
- 作为云用户，我不需要担心 API 凭据 - 它们是预先配置的。

### 功能要求

**凭证配置（仅限自托管）：**
- 组织 → 平台凭证下的设置页面。
- 对于每个支持的平台，显示：平台名称、平台图标、状态（已配置/未配置）、所需凭据的字段。

| 平台 | 所需凭据 |
|----------|---------------------|
| Facebook / Instagram | 应用程序 ID、应用程序密钥（Facebook 两者使用相同的应用程序）|
| LinkedIn | 客户 ID、客户密码 |
| TikTok | 客户端密钥、客户端密钥 |
| YouTube | 客户端 ID、客户端密钥 (Google Cloud OAuth) |
| Pinterest | 应用程序 ID、应用程序密钥 |
| 线程 | 相同的 Facebook 应用程序（使用 Instagram 图表 API 权限） |
| Bluesky | 无需应用程序凭据（使用 AT 协议以及用户的句柄 + 应用程序密码） |
| Google 商家资料 | 与 YouTube 相同的 Google Cloud OAuth 应用（其他范围） |
| Mastodon | 每实例 OAuth 应用程序注册（首次连接时自动创建） |

- 凭证在组织级别输入一次并在所有工作区之间共享。
- 凭据静态加密存储（AES-256-GCM，从服务器端密钥派生的加密密钥，不存储在数据库中）。
- 每个平台的“测试连接”按钮尝试初始化 OAuth 流程并报告成功或失败。
- 回调/重定向 URI 自动生成并显示，以便复制粘贴到平台的开发人员控制台中。

**云版本：**
- 凭据设置页面对所有用户（包括组织所有者）隐藏。用户永远不会在云版本上看到平台 API 凭证或与之交互。
- 云版本的平台 API 凭证由平台开发人员专门通过服务器端环境变量进行配置。每个平台的凭据都按照以下命名约定存储为环境变量：
  - `PLATFORM_FACEBOOK_APP_ID` / `PLATFORM_FACEBOOK_APP_SECRET`
  - `PLATFORM_LINKEDIN_CLIENT_ID` / `PLATFORM_LINKEDIN_CLIENT_SECRET`
  - `PLATFORM_TIKTOK_CLIENT_KEY` / `PLATFORM_TIKTOK_CLIENT_SECRET`
  - `PLATFORM_GOOGLE_CLIENT_ID` / `PLATFORM_GOOGLE_CLIENT_SECRET`（由 YouTube 和 Google 商家资料共享）
  - `PLATFORM_PINTEREST_APP_ID` / `PLATFORM_PINTEREST_APP_SECRET`
- 在应用程序启动时，系统读取这些环境变量并填充 `PlatformCredential` 条记录以获取特殊的系统级“云”组织上下文。如果环境变量丢失或为空，则该平台会在社交帐户连接流程中标记为“即将推出”。
- 开发人员绝不能将这些凭据提交给源代码管理。在生产中，凭证通过托管平台的机密管理注入（例如，Heroku 配置变量、AWS Secrets Manager、Docker 机密、Kubernetes 机密）。
- 云版本的回调/重定向 URI 被硬编码到云应用程序的域 (e.g., `https://app.platform.com/auth/callback/{platform}`)。开发人员在设置共享应用程序时在每个平台的开发人员控制台中配置这些 URI。
- 如果需要轮换平台的凭据，开发人员将更新环境变量并重新启动应用程序。现有用户 OAuth 令牌在过期之前保持有效。

**凭证轮换：**
- 管理员可以随时更新凭据。连接帐户的现有 OAuth 令牌在过期之前仍然有效。
- 如果凭据被撤销或更改而导致现有令牌失效，系统会将受影响的社交帐户标记为“需要重新连接”并通知工作区经理。

### 数据模型
- `PlatformCredential`：id、organization_id、平台（枚举）、凭据（加密的 json）、is_configured（布尔值）、tested_at、test_result（枚举：成功、失败、未测试）、created_at、updated_at。

### 依赖关系
- F-2.4（发布引擎）- 将这些凭据用于 API 调用。
- F-3.1（社交收件箱）- 使用这些凭据来阅读消息。
- F-4.1（分析）- 使用这些凭据来获取指标。

### 验收标准
- 自托管：输入有效的 Facebook 凭据并单击“测试连接”会在 10 秒内返回成功状态。
- 自托管：尝试连接未配置凭据的平台的社交帐户会显示一条明确的错误消息，将管理员引导至凭据页面。
- 云：凭证页面对所有用户（包括组织所有者）完全隐藏。
- 凭证绝不会在 API 响应、日志或错误消息中公开。 UI 中仅显示机密的最后 4 个字符以供识别。

## F-1.6 - 可配置的默认值和平台设置

- 组织设置和工作区设置都有一个“默认”选项卡，该选项卡组织成与上述类别匹配的可折叠部分。
- 每个设置显示：标签、当前值、默认值（如果当前值与默认值匹配，则显示为灰色）、简要说明以及适合数据类型的输入字段（数字输入、文本输入、切换、时间选择器）。
- 工作区设置显示每个设置的“从组织继承”切换。启用后，工作区使用组织级别值，并且输入字段被禁用。
- 更改会在模糊时立即保存或在每个部分的明确“保存”按钮上保存。成功的 toast 确认保存。
- 每个部分的“重置为默认值”按钮可将该部分中的所有设置恢复为其默认值。
- 更改对所有未来操作立即生效 - 它们不会追溯影响已安排的帖子、已发送的提醒或已生成的重复。

### 数据模型
- `OrgSetting`：id、organization_id、键（字符串，每个组织唯一）、值（json）、updated_at。
- `WorkspaceSetting`：id、workspace_id、键（字符串，每个工作区唯一）、值（json、可为空 - null 表示从 org 继承）、updated_at。
- 设置键遵循命名空间约定：`approval.internal_reminder_hours`、`publishing.first_comment_delay_seconds`、`inbox.sync_interval_minutes` 等。
- 辅助函数 `get_setting(workspace_id, key)` 返回工作区级别值（如果设置），否则回退到组织级别值，否则回退到应用程序级别默认值。

### 依赖关系
- 所有功能都引用这些设置而不是硬编码值。
- F-1.1、F-1.2（组织/工作空间）- 属于这些实体的设置。
- F-2.2（批准）- 提醒间隔、最大提醒数。
- F-2.3（日历）- 重复预测、队列警告。
- F-2.4（发布引擎） - 重试逻辑、首次评论延迟、轮询间隔。
- F-3.1（收件箱） - 同步间隔、自动解析、SLA 计时器。
- F-4.1（分析）- 收集窗口、最佳时间阈值。
- F-7.1（通知）- 批处理延迟、安静时间、摘要模式。
- F-1.4（客户端）- 魔术链接到期、提醒间隔、电子邮件主题模板。
- F-5.1（身份验证）- 会话持续时间、登录速率限制、2FA 强制执行。

### 验收标准
- 在工作区设置中将“内部审核提醒间隔”从 24 小时更改为 12 小时，会导致该工作区中待处理帖子的下一个提醒在 12 小时（而不是 24 小时）后触发。
- 保留为“从组织继承”的工作区设置正确使用组织级别值。更改组织级别值会传播到所有继承工作区。
- 显式设置为自定义值的工作区设置不受组织级别默认值更改的影响。
- “重置为默认值”可恢复某个部分中的所有设置，并且 UI 会立即反映更改。
- 自托管管理员可以通过环境变量更改发布轮询间隔；后台工作人员在下次重新启动时选择新的间隔。
- `get_setting()` 函数在级联后返回正确的值：工作区覆盖 → 组织覆盖 → 应用程序默认值。

## F-1.7 - 客户加入流程

### 目的
定义新客户加入平台的端到端流程 - 从工作区创建到社交帐户连接再到首次内容审核。对于代理机构来说，这是至关重要的首次体验，必须快速且无摩擦。

### 用户故事
- 作为工作区经理，我可以在 10 分钟内加入新客户：创建工作区、连接他们的帐户、邀请他们并提交初始内容以供审核。
- 作为客户，我会收到一封清晰的品牌电子邮件，邀请我查看我的第一篇帖子 - 无需了解该平台。
- 作为机构管理员，我可以使用客户授予我的访问权限代表客户连接社交帐户（常见机构做法）。
- 作为客户，我可以通过我的代理机构发送给我的引导链接连接我自己的社交帐户，而无需访问完整的平台。

### 功能要求

**第 1 步：创建工作区**
- 代理机构成员（管理员或所有者）为客户创建一个新工作区 (F-1.2)。
- 最小输入：工作区名称。所有其他设置（时区、品牌颜色、审批工作流程）都可以稍后配置。
- 创建后，用户进入新工作区，并收到“入门”清单提示（见下文）。

**第2步：社交帐户连接**

两种连接方法，取决于代理-客户关系：

*方法 A - 代理机构直接连接账户（最常见）：*
- 该机构已经拥有对客户社交媒体帐户的管理员/编辑访问权限（标准代理实践 - 客户通过每个平台的本机权限系统授予访问权限）。
- 机构成员在工作区中单击“连接帐户”，并自行完成 OAuth 流程，使用自己的 Facebook/Instagram/LinkedIn/等进行身份验证。对客户端页面/个人资料具有必要权限的凭据。
- 这是F-2.5中描述的标准流程。

*方法 B - 客户通过邀请链接连接自己的帐户：*
- 对于喜欢连接自己帐户的客户（注重隐私的客户或尚无管理员访问权限的机构）。
- 机构成员在工作区设置 → 社交帐户中单击“邀请客户连接帐户”。
- 系统生成单一用途、有时间限制的URL（“连接链接”）。该链接通过电子邮件发送给客户或复制到剪贴板以供共享。
- 连接链接会打开一个带品牌的最小页面（如果已配置，则为白色标签）：
  1. 显示机构名称和工作区名称（“将您的帐户连接到[机构名称]”）。
  2. 通过“连接”按钮列出支持的平台。
  3. 指导客户端完成每个平台的 OAuth 流程。
  4. 每次成功连接后，都会显示绿色复选标记和连接的帐户名称/头像。
5. 有一个“完成”按钮，用于关闭页面并通知代理团队帐户已连接。
- 连接链接 NOT 授予客户端对平台仪表板、编辑器、日历或任何其他功能的访问权限。它仅用于连接社交帐户。
- 连接链接过期：可配置，默认 7 天（引用 F-1.6 设置 - 将 `client_connection_link_expiry_days` 添加到工作区设置）。
- 连接链接每个帐户连接只能使用一次，但在连接多个帐户时仍保持活动状态，直至过期。
- 代理成员可以随时撤销或重新生成连接链接。

**步骤 3：客户邀请（可选，与步骤 2 并行）**
- 代理机构邀请客户以“客户”角色 (F-1.3) 进入工作区，以便他们稍后可以批准内容。
- 此步骤独立于帐户连接 - 可以在帐户连接之前、期间或之后邀请客户。
- 邀请使用标准流量（F-1.3）或魔力链接流量（F-1.4）。

**第 4 步：第一批内容**
- 帐户连接后，机构将创建并安排（或提交审批）第一批帖子。
- 这里不需要特殊功能 - 这使用标准编辑器 (F-2.1) 和批准工作流程 (F-2.2)。

**入门清单：**
- 当新创建工作区且尚未完成关键设置步骤时，工作区仪表板顶部的显着位置会显示“入门”清单卡。
- 检查清单项目：

| 步骤 | 完成条件 | 操作按钮 |
|------|---------------------|---------------|
| 连接社交帐户 | 至少 1 个社交帐户连接到此工作区 | “连接帐户” → 打开帐户连接流程 |
| 邀请您的客户 | 在此工作区中至少有 1 名具有客户角色的成员 | “邀请客户”→ 打开邀请表单 |
| 设置审批工作流程 | 已明确设置审批工作流程模式（非默认） | “配置”→ 打开工作区设置 |
| 创建您的第一个帖子 | 在此工作区中至少创建了 1 个帖子（任何状态） | “创建帖子”→ 打开作曲家 |
| 设置发布计划 | 为任何连接的帐户配置至少 1 个发布槽 | “设置计划”→ 打开发布槽配置 |

- 每个完成的步骤都会显示一个复选标记。不完整的步骤会显示带有操作按钮的圆形轮廓。
- 清单可以被取消（“不再显示”） - 一旦取消，它就不会重新出现。解雇按工作区的每个用户存储。
- 该清单纯粹是提供信息和建议 - 它不会阻止任何功能。无论清单是否完成，用户都可以随时使用任何功能。

**连接链接页面（详细规格）：**

*布局：*
- 全页、居中的卡片布局。没有侧边栏，没有导航 - 这是一个独立页面。
- 标题：机构徽标（来自白标签或平台徽标，如果未配置）、“连接您的社交帐户”标题、工作区名称副标题。
- 主体：平台卡网格。每张卡片显示：平台图标、平台名称、“连接”按钮（或连接后带有帐户名/头像的“已连接✓”）。
- 页脚：“需要帮助吗？联系[来自白标设置的机构电子邮件，或平台支持电子邮件]。”

*行为：*
- 单击“连接”将启动该平台的标准 OAuth 流程 (F-2.5)。 OAuth 回调重定向回此页面。
- 连接帐户后，卡片会更新以显示已连接的帐户名称和带有绿色复选标记的头像。
- 客户端可以跨多个平台连接多个帐户。
- 底部的“完成 - 通知 [机构名称]”按钮向所有工作区经理发送应用内 + 电子邮件通知，列出已连接的帐户。

*安全：*
- 连接链接令牌是加密安全的（32 字节，URL 安全的 base64）。
- 令牌的范围仅限于特定工作区。它不能用于访问任何其他工作区或组织数据。
- 该页面不公开任何现有的工作区数据（没有帖子、没有日历、没有分析、没有其他连接的帐户）。
- 速率限制：每个令牌每小时最多 20 个 OAuth 流启动（防止滥用）。

### 数据模型
- `ConnectionLink`：id、workspace_id、令牌（字符串、唯一、索引）、created_by（用户id）、expires_at（日期时间）、revoked_at（日期时间、可为空）、created_at。
- `ConnectionLinkUsage`：id、connection_link_id、social_account_id（FK - 已连接的帐户）、connected_at（日期时间）。
- `OnboardingChecklist`：id、user_id、workspace_id、is_dismissed（布尔值）、dismissed_at（日期时间、可为空）。

### 依赖关系
- F-1.2（工作空间）- 工作空间创建。
- F-1.3 (RBAC) - 客户端角色邀请。
- F-1.4（客户端）- 入职后的客户端访问。
- F-1.6（可配置默认值）- 连接链接到期设置。
- F-2.5（社交帐户连接）- OAuth 流。
- F-5.2（白标）- 连接链接页面上的品牌。
- F-7.1（通知）- 客户端完成连接帐户时的通知。

### 验收标准
- 工作区管理员只需点击 3 次即可生成连接链接并共享。
- 收到连接链接的客户端可以在 60 秒内连接 Instagram Business 帐户（不包括 Instagram 身份验证页面上的时间）。
- 客户连接帐户并单击“完成”后，工作区管理员会在 30 秒内收到一条通知，列出已连接的帐户。
- 连接链接页面显示零平台数据 - 没有帖子，没有分析，没有其他帐户。只有连接按钮和连接帐户确认。
- 过期的连接链接会显示友好的“此链接已过期 - 请联系您的代理机构”页面。
- “开始”清单正确反映了完成状态：连接帐户立即勾选“连接社交帐户”。
- 忽略清单仍然存在 - 刷新页面不会将其恢复。

## F-2.1 - 后期作曲家

### 目的
中央内容创建界面。用户撰写单个帖子并根据平台对其进行自定义。编写者生成一个流入审批工作流程和/或调度系统的 Post 实体。

### 用户故事
- 作为编辑，我可以撰写帖子，选择多个目标平台，并查看每个平台的实时预览。
- 作为编辑，我可以为同一作曲家的每个平台定制不同的标题、媒体和主题标签。
- 作为编辑，我可以将图像、视频和轮播附加到我的帖子中。
- 作为贡献者，我可以撰写草稿，但无法安排或发布它。
- 作为编辑，我可以使用 AI 生成标题变体、建议主题标签，并以不同的语气重写我的文本。
- 作为编辑，我可以将帖子保存为模板以供重复使用。

### 功能要求

**作曲家布局：**
- 作曲家是一个专用的完整页面（路线：`/workspace/{id}/compose`），而不是模式或弹出窗口。导航到作曲家将完全替换当前视图。侧边栏对于工作区导航仍然可见，但主要内容区域完全专用于作曲家。
- 编辑器左上角的“后退”按钮可让用户返回到之前的视图（日历、草稿列表等）。如果有未保存的更改，则会出现确认对话框。
- 作曲家页面分为三个面板：
- 左侧面板：平台选择器（当前工作区中每个已连接帐户的复选框）和媒体上传区域。
- 中心面板：带有以下控件的标题文本编辑器：
  - 不支持富文本（社交平台使用纯文本）。编辑器是一个带有字符数的纯文本区域。
  - 字符数显示每个选定平台的限制（例如，LinkedIn：3,000；Instagram：2,200；Facebook：63,206；Bluesky：300；Mastodon：500 或实例限制）。
  - 如果标题超出任何选定平台的限制，该平台的计数器将变为红色并显示警告。
  - 表情符号选择器可通过按钮或键盘快捷键访问。
  - 主题标签自动建议：输入“#”会打开一个下拉菜单，其中包含工作区默认主题标签（来自 F-1.2 设置）和最近使用的主题标签。
  - 提及自动建议：输入“@”会打开一个下拉菜单（根据平台 API 支持的连接帐户的最近交互填充；否则为自由文本）。
- 右侧面板：每个选定平台的实时预览。预览呈现的帖子大致与平台上显示的一样（标题截断、媒体布局、个人资料图片、帐户名称）。

**特定于平台的定制：**
- 默认情况下，所有平台共享相同的标题和媒体。
- 每个平台的“自定义[平台]”切换允许覆盖：标题文本、媒体选择/排序、主题标签、每个图像的替代文本、第一条评论文本。
- 覆盖按 PlatformPost 存储（请参阅 F-2.4）。基帖保留“共享”版本。
- 不支持某功能的平台会隐藏相关控件（例如，Pinterest 不支持第一条评论 - 当 Pinterest 是唯一选定的平台时，该字段会被隐藏）。

**媒体附件：**
- 媒体选择器允许：从设备上传、从工作区媒体库中选择 (F-6.1)、搜索库存媒体（Unsplash、Pexels、GIPHY - 请参阅 F-5.3）、打开 Canva（请参阅 F-5.3）。
- 可以附加多个媒体项目。作曲家根据选择检测帖子类型：
  - 1 张图片 → 单张图片帖子。
  - 2–10 张图像 → 轮播（在支持它的平台上；否则，第一张图像仅带有警告）。
  - 1 个视频 → 视频帖子/卷轴/短片（取决于平台和时长）。
  - 图像+视频混合 → 支持平台上的轮播（Instagram、Facebook、LinkedIn）；对他人的警告。
- 媒体排序：拖放以对轮播中的图像/视频重新排序。
- 每个图像的替代文本字段（辅助功能）。
- 媒体验证：创作者根据目标平台的要求检查每个附加的媒体项目并显示警告：
  - 图像尺寸（每个平台的最小/最大）。
  - 图像文件大小（每个平台的最大值）。
  - 视频时长（例如，Instagram Reel：3–90 秒；YouTube Short：最长 60 秒；TikTok：最长 10 分钟）。
  - 视频文件大小。
  - 宽高比警告（例如，“此图像为 16:9，但 Instagram feed 帖子在 4:5 时效果最佳”）。
  - 轮播中的项目数量（Instagram 最多：20；LinkedIn 最多：20；Facebook 最多：10）。

**帖子类型：**
- 标准帖子（文本+可选媒体）。
- 卷轴/短片（垂直视频，通过宽高比和持续时间检测）。
- 故事（Instagram、Facebook - 短暂、24 小时）。
- 轮播（多个图像/视频）。
- 投票（LinkedIn 仅在 v1 中）。
- 文章（仅限 LinkedIn - 带标题的长文本）。
- 视频（YouTube - 带有标题、描述、标签、可见性、类别字段）。
- Pin（Pinterest - 带板选择，链接 URL，标题，描述）。

选择帖子类型后，撰写者会调整其字段：
- YouTube 视频显示：标题（必填，最多 100 个字符）、描述（最多 5,000 个字符）、标签、可见性（公开/不公开/私人）、类别下拉列表、缩略图上传。
- Pinterest pin 显示：板选择器（从连接的帐户获取）、链接 URL、标题、描述。
- LinkedIn 文章显示：标题、正文（具有基本格式的长文本）、封面图片。

**第一条评论：**
- 标题下方会出现“第一条评论”文本字段。
- 默认文本是从工作区设置 (F-1.2) 中预先填充的（如果已配置）。
- 第一条评论在主帖发布后立即发布（在同一发布作业中）。
- 支持：Instagram、Facebook、LinkedIn、YouTube。对于不支持它的平台隐藏。

**内容类别：**
- 用于将帖子分配给内容类别的下拉菜单（例如“教育”、“促销”、“幕后”）。
- 类别按工作区定义（在工作区设置中管理）。
- 类别用于：日历过滤、分析过滤、基于队列的调度 (F-2.3)。
- 一篇文章可以属于零个或一个类别。

**标签/标签：**
- 除了类别之外，帖子还可以具有自由格式的标签（例如“campaign:summer2026”、“client-approved”）。
- 标签用于过滤和搜索日历和分析中的帖子。

**内部注释：**
- 仅限团队注释的文本字段（例如，“客户特别要求我们使用这张照片”、“第三季度活动的一部分”）。
- 具有客户角色的用户永远看不到内部注释。
- 内部注释不包含在帖子预览或发布的内容中。

**人工智能辅助：**
- 作曲家工具栏中的“AI”按钮会在作曲家右侧打开一个 AI 助手面板（暂时覆盖或替换预览面板）。
- AI 助手需要至少一个在组织级别配置的 AI 提供程序（请参阅 F-5.3 - AI 集成）。如果未配置提供程序，该按钮会显示一个工具提示，引导管理员进行设置。
- **提供商/模型选择器（每代覆盖）：** 在 AI 面板顶部，一个紧凑的下拉列表显示当前选择的提供商和模型（默认为组织范围的默认值）。用户可以更改提供程序（OpenAI、Anthropic、OpenRouter - 仅显示已配置的提供程序）和模型（该提供程序的模型下拉列表，与 F-5.3 设置中的选项匹配）。此选择在 Composer 会话期间持续存在，但不会更改组织范围内的默认设置。切换提供商/模型会对下一个 AI 操作生效 - 它不会重新运行前几代。
- 人工智能能力：
  - **生成标题：** 给定媒体（如果图像 - 如果 AI 提供商支持，则作为视觉输入发送）和可选上下文（例如，“为咖啡店的 Instagram 宣传新拿铁咖啡撰写标题”），生成 3 个标题变体。生成按钮上方的文本输入字段可让用户提供上下文/说明。
  - **重写语气：** 选择现有的标题文本并选择语气（专业、休闲、幽默、鼓舞人心、紧急）。人工智能以这种语气重写了标题。
  - **建议主题标签：** 根据标题和媒体，建议 10-15 个相关主题标签。用户可以单击将单独的主题标签添加到标题或第一个评论中。
  - **翻译：** 将标题翻译成所选语言。语言列表：互联网用户使用最多的 20 种语言。
  - **缩短/延长：** 将标题重写为更短（例如，适合 Bluesky 的 300 个字符限制）或更长（扩展一个简短的想法）。
- 所有 AI 操作均通过所选提供商的 API 在服务器端执行。请求包括每代选择器中指定的模型。
- 用户可以接受、编辑或放弃任何人工智能生成的建议。
- AI 生成的内容不会自动插入 - 用户始终在替换标题之前进行确认。 “插入”按钮将选定的建议放入标题字段中； “放弃”按钮可清除建议。

**模板：**
- “另存为模板”按钮将当前帖子的配置（标题、媒体占位符、类别、平台选择、第一条评论、主题标签）保存为可重复使用的模板。
- 模板的范围仅限于工作区。
- 模板有名称（必需）和可选描述。
- 编辑器中的“使用模板”按钮加载模板，填充所有字段。然后用户可以照常修改和安排。
- 模板在工作区设置的“模板”部分中进行管理（列出、重命名、删除）。

**保存草稿：**
- 当用户编辑时，作曲家每 30 秒自动保存到草稿。
- 如果用户尝试离开，则会警告未保存的更改。
- 草稿出现在内容日历 (F-2.3) 中，状态为“草稿”。
- 侧边栏或日历过滤器中的“草稿”部分显示工作区的所有草稿。

**作曲家操作（底栏）：**
- “保存草稿”- 无需安排即可保存。
- “提交审批” - 如果工作区审批工作流程是“可选”或“必需”，则可见。将帖子转换为“pending_review”状态。
- “时间表”- 打开日期/时间选择器。如果用户的角色允许直接发布并且审批工作流程允许，则可见。
- “立即发布”- 立即发布。仅当用户的角色允许直接发布时才可见。
- “添加到队列”- 将帖子添加到所选队列中的下一个可用槽位（请参阅 F-2.3）。如果配置了队列则可见。

### 数据模型
- `Post`：id、workspace_id、author_id、状态（枚举：草稿、pending_review、pending_client、批准、计划、发布、已发布、部分发布、失败）、标题（文本）、first_comment（文本）、category_id（可为空）、标签（json 字符串数组）、internal_notes（文本）、template_source_id（可为空）、scheduled_at (datetime, nullable)、published_at (datetime, nullable)、proposal_publish_at (datetime, nullable - 可选草稿阶段建议发布时间，与 Scheduled_at 不同)、created_at、updated_at。
- `PlatformPost`：id，post_id，social_account_id，platform_specific_caption（文本，可为空 - 空表示使用基本标题），platform_specific_media（json，可为空），platform_specific_first_comment（文本，可为空），platform_post_id（字符串，可为空 - 发布后填充），publish_status（枚举：待处理，已发布，失败），publish_error （文本，可为空），published_at（日期时间，可为空）。
- `PostMedia`：id、post_id、media_asset_id、位置（整数，用于排序）、alt_text（文本，可为空）、platform_overrides（json - 例如，{“instagram”：{"crop": "4:5"}}）。
- `PostVersion`：id、post_id、version_number（整数）、快照（json - 保存时的完整帖子状态）、created_by、created_at。
- `PostTemplate`：id、workspace_id、名称、描述、template_data（json - 标题、媒体引用、类别、平台选择、第一条评论、主题标签）、created_by、created_at、updated_at。

### 依赖关系
- F-1.2（工作区）- 工作区范围、默认主题标签、第一个评论模板。
- F-1.3 (RBAC) - 角色决定哪些作曲家操作可见。
- F-2.2（审批工作流程）- 确定职位状态转换。
- F-2.3（日历和日程安排）- 预定的帖子出现在日历上。
- F-2.4（发布引擎）- 执行实际发布。
- F-5.3（集成 - AI） - AI 辅助功能。
- F-5.3（集成 - Canva/Stock） - 媒体采购。
- F-6.1（媒体库）-媒体选择和存储。

### 验收标准
- 使用 3 个平台目标（Instagram、LinkedIn、Facebook）撰写帖子并自定义 LinkedIn 标题可正确显示所有 3 个预览并单独存储 LinkedIn 覆盖。
- 将 11 张图像附加到针对 Instagram 的帖子时会显示一条警告，指出 Instagram 轮播最多支持 20 张图像，并会显示针对其他限制较低的平台的警告。
- 当配置 API 密钥时，AI Assist 在 5 秒内生成 3 个字幕建议。在 AI 面板中切换提供商/模型可以正确地将下一代路由到所选提供商。
- 自动保存每 30 秒创建一个草稿；关闭并重新打开作曲家可以恢复草稿。
- 贡献者角色用户只能看到“保存草稿”和“提交审批”按钮 - 没有“计划”或“立即发布”。
- 字符计数器随着用户输入而实时更新，并正确反映每个平台的限制。

## F-2.2 - 审批工作流程

### 目的
可配置的内容审核流程，确保帖子在发布前经过合适的人员审核。支持内部团队审核和外部客户批准。

### 用户故事
- 作为工作区所有者，我可以配置帖子在安排之前是否需要批准。
- 作为经理，当帖子提交审核时我会收到通知，并且可以批准或请求更改。
- 作为客户，当帖子可供我审核时，我会收到一封电子邮件，并且可以从客户端门户批准或拒绝它们。
- 作为编辑，我可以查看我的帖子的批准状态并回复审稿人的反馈。

### 功能要求

**工作流程模式（在 F-1.2 中为每个工作区配置）：**

| 模式 | 行为 |
|------|----------|
| `none` | 帖子直接从作曲家进入“已计划”或“草稿”状态。没有审核步骤。 |
| `optional` | 作者选择：“保存草稿”、“提交审批”或“安排”（如果角色允许）。 |
| `required_internal` | 所有帖子必须经过具有“经理”或“所有者”角色的用户批准才能安排。在帖子获得批准之前，“计划”和“立即发布”按钮将被隐藏。 |
| `required_internal_and_client` | 与 `required_internal` 相同，但在内部批准后，帖子将转换为“pending_client”，并且客户也必须在安排之前批准。 |

**状态转换：**

```
draft ──────────────> scheduled (mode: none, or optional + author chooses to schedule)
draft ──> pending_review ──> approved ──> scheduled (mode: required_internal)
draft ──> pending_review ──> approved ──> pending_client ──> approved ──> scheduled (mode: required_internal_and_client)

At any stage:
  pending_review ──> changes_requested ──> (author edits) ──> pending_review (resubmit)
  pending_client ──> changes_requested ──> (author edits) ──> pending_review (restart)
```

- 当客户请求更改时，帖子将返回“changes_requested”并通知内部团队。该帖子在返回给客户之前会重新进入内部审核周期。
- 被拒绝的帖子（被内部审阅者或客户）转为“被拒绝”状态。作者可以编辑并重新提交或删除帖子。

**批准行动：**

*对于内部审阅者（经理、所有者）：*
- “批准”- 将帖子移至“已批准”（或“pending_client”，如果需要客户批准）。
- “请求更改” - 需要注释来解释要修复的内容。帖子移至“changes_requested”。作者已收到通知。
- “拒绝” - 需要评论。帖子移至“已拒绝”。作者已收到通知。

*对于客户（通过客户端F-1.4）：*
- “批准”- 将帖子移至“已批准”→“已安排”。
- “请求更改” - 需要评论。帖子移回“changes_requested”。
- “拒绝” - 需要评论。帖子移至“已拒绝”。

**评论：**
- 每个帖子有两种类型的评论：
  - **内部评论：** 仅对组织成员（而非客户）可见。用于有关该帖子的团队讨论。
- **外部评论：** 团队和客户都可见。用于与客户就该帖子进行沟通。
- 评论是线程化的（回复特定评论）。
- 评论支持@提及工作区成员（触发通知）。
- 评论在每个线程中按时间顺序显示。
- 评论中的文件附件：仅图像（用于共享参考屏幕截图等）。每个附件最多 5MB。

**批量操作：**
- 在审批队列视图中，审阅者可以选择多个帖子并且：
  - 批准所有选定的内容。
  - 拒绝所有选定的内容（带有共享评论）。
- 批量批准仅适用于内部审核者，不适用于客户。

**版本历史：**
- 每次在初始创建后编辑帖子时，都会保存一个新版本（请参阅 F-2.1 中的帖子版本）。
- 审批视图显示“查看更改”按钮，显示当前版本和上次审核版本之间的差异。
- 差异突出显示：添加的文本（绿色）、删除的文本（红色）、更改的媒体（并排缩略图）。

**自动提醒：**
- 如果帖子处于“pending_review”状态的时间超过可配置的小时数（默认值：24 小时），系统会向所有符合资格的审阅者发送提醒通知。
- 如果帖子在“pending_client”中的停留时间超过可配置的小时数（默认值：48），系统会向客户端发送提醒。
- 每个阶段每个帖子最多 2 个自动提醒。之后，工作区经理会收到帖子已停止的通知。
- 每个工作区的提醒间隔均可配置。

**批准队列视图：**
- 工作区级别：“待批准”选项卡/页面显示此工作区中等待审核的所有帖子，按计划日期排序（最早的第一个）。
- 组织级别（针对管理员/所有者）：所有工作区中的“所有待批准”，按工作区分组。

### 数据模型
- `ApprovalAction`：id、post_id、user_id、操作（枚举：已提交、已批准、更改请求、已拒绝、重新提交）、评论（文本、可为空）、created_at。
- `PostComment`：id、post_id、author_id、parent_comment_id（可为空，用于线程）、正文（文本）、可见性（枚举：内部、外部）、attachment_url（可为空）、created_at、updated_at、deleted_at。
- 后状态转换是通过状态机在应用程序级别强制执行的。无效的转换会返回错误。

### 依赖关系
- F-1.2（工作空间）- 工作流程模式配置。
- F-1.3 (RBAC) - 确定谁可以批准。
- F-1.4（客户端）- 客户端审批界面。
- F-2.1（作曲家）-后期创作和编辑。
- F-7.1（通知）- 批准请求通知、提醒。

### 验收标准
- 在 `required_internal` 模式下，编辑者无法安排帖子 - 不会呈现“安排”按钮。经理批准后，帖子会自动安排在作者最初选择的时间。
- 在 `required_internal_and_client` 模式下，请求更改的客户端将帖子发送回“changes_requested”并通知内部团队。该帖子在返回给客户之前必须再次经过内部审核。
- 版本差异正确显示文本添加、删除和媒体更改。
- 自动提醒会按照配置的时间间隔触发，并在 2 次提醒后停止。
- 批量批准 20 个帖子可在 3 秒内完成。

## F-2.3 - 内容日历和日程安排

### 目的
视觉日历是机构的日常运营中心。它提供跨平台所有内容的概览，支持拖放调度、基于队列的自动调度和批量导入。

### 用户故事
- 作为编辑，我可以在可视日历上查看所有计划的、草稿的和待处理的帖子。
- 作为经理，我可以拖动帖子将其重新安排到不同的日期和时间。
- 作为编辑，我可以设置一个内容队列，在我喜欢的时间自动发布帖子。
- 作为经理，我可以从 CSV 文件中批量导入一个月的帖子。
- 作为组织管理员，我可以查看跨工作区日历，一目了然地查看所有客户的内容。

### 功能要求

**日历视图：**

*月视图：*
- 网格布局，以天为列，以周为行。
- 每天的单元格显示：每个平台的帖子计数徽章（图标），以及最多 3 张帖子预览卡。
- 如果一天的帖子超过 3 个，“+N 更多”链接会扩展该天。
- 帖子按状态进行颜色编码：草稿（灰色）、待批准（橙色）、已计划（蓝色）、已发布（绿色）、失败（红色）。
- 单击明信片将打开加载该帖子的作曲家 (F-2.1)。

*周视图：*
- 7 列布局，每小时行。
- 帖子在预定时间定位为卡片，显示：平台图标、标题片段（前 50 个字符）、第一个媒体项目的缩略图。
- 卡片可以垂直拖动（更改时间）或水平拖动（更改日期）。

*日视图：*
- 单日时间线，按小时划分。
- 更详细的明信片显示：完整平台图标集、标题（前 100 个字符）、所有媒体缩略图、作者头像、状态徽章。

*列表视图：*
- 表格格式：日期、时间、platform(s)、标题片段、状态、作者、类别。
- 可按任何列排序。
- 可过滤（见下文）。
- 分页：每页 50 个帖子。

**过滤（适用于所有视图）：**
- 按平台：每个连接平台的复选框。多选。
- 按状态：草稿、pending_review、pending_client、已批准、已计划、已发布、失败。多选。
- 按类别：工作区内容类别的下拉列表。多选。
- 按作者：工作区成员的下拉列表。多选。
- 按标签：通过现有标签自动完成文本输入。
- 按日期范围：开始日期和结束日期选择器。
- 过滤器可组合（AND 逻辑）。有源过滤器在日历上方显示为可拆卸芯片。

**拖放重新安排：**
- 在周和日视图中，可以将帖子拖到新的时间段。
- 拖动帖子会更新其 `scheduled_at` 时间戳。
- 只能拖动状态为“草稿”、“已批准”或“已安排”的帖子。待批准和已发布的帖子被锁定。
- 如果新时间已过去或距当前时间不超过 5 分钟，则会出现确认对话框。
- 拖放遵循 RBAC：只有可以编辑帖子的用户（自己的帖子为编辑+，其他帖子为经理+）才能拖动。

**最佳时间建议：**
- 对于每个连接的社交帐户，系统会分析历史参与数据（来自 F-4.1）以确定最佳发布时间。
- 建议的时间在日历上显示为微妙的突出显示槽（例如，时间行上的浅绿色背景）。
- 计算：针对一周中的每个小时，计算过去 90 天内该小时内发布的帖子的平均参与率。每天最重要的 3 小时会突出显示。
- 如果数据不足（过去 90 天内少于 10 个帖子），则不会显示任何建议。工具提示解释了原因。

**时间段/发布时间表：**
- 每个社交帐户，用户可以定义重复的时间段（例如，“周一、周三、周五上午 9 点和下午 6 点”）。
- 时隙表示基于队列的调度的默认发布时间。
- 时间段在工作区设置 → 帐户设置中管理。
- 时间段在日历上以虚线轮廓显示在它们重复发生的日期/时间上。

**基于队列的调度：**
-“队列”由以下内容定义：内容类别和一组时隙。
- 当帖子“添加到队列”（来自作曲家）时，系统会将其分配到该队列的下一个可用时隙。
- 每个工作区可以存在多个队列（例如，“教育内容 - MWF 上午 9 点”和“促销 - 中午 12 点”）。
- 队列管理：以有序列表的形式查看队列。帖子可以在队列中重新排序（拖放）。重新排序会更改每个帖子分配到的位置。
- 如果队列在接下来的 30 天内没有可用空位，则会向用户发出警告。

**批量调度（CSV导入）：**
- 上传 CSV 或 TSV 文件，每个帖子一行。
- 列：日期 (YYYY-MM-DD)、时间（HH:MM、24 小时格式）、时区（可选 - 默认为工作区时区）、platform(s)（逗号分隔的平台标识符：instagram、facebook、linkedin、tiktok、youtube、pinterest、threads、bluesky、 google_business、mastodon）、标题（文本）、media_url（图像/视频的 URL - 导入时获取并存储在媒体库中）、类别（名称 - 与现有类别匹配或创建）、标签（以逗号分隔）、first_comment（文本）。
- 列映射：上传后，用户会看到一个列映射界面，其中将每个 CSV 列分配给帖子字段。系统尝试根据列标题进行自动检测。
- 验证：在导入之前，系统会验证所有行并显示每行的错误（例如，“第 12 行：日期已过去”、“第 34 行：不支持平台‘twitter’”）。用户可以修复 CSV 并重新上传或跳过无效行。
- 导入限制：每次上传无限制帖子（以 100 个为批次处理）。
- 媒体获取：媒体 URL 异步下载。媒体下载失败的帖子将创建为草稿，并带有警告。
- 如果工作区设置需要，导入的帖子会进入审批工作流程。

**重复帖子：**
- 安排帖子时，可以使用“定期”切换。
- 选项：每 N 天/周/月重复一次。结束日期（可选 - 如果未设置，则无限期重复）。
- 系统最多提前 90 天为每次重复创建单独的过帐记录。随着时间的推移，后台作业会生成新的重复作业。
- 每个重复都是一个独立的帖子，可以单独编辑或取消，而不影响其他重复。
- 重复帖子上会出现“重复”徽章，并带有“查看所有重复”的链接。

**假期/活动日历：**
- 日历上的叠加显示社交媒体意识日（例如“世界咖啡日”、“国际妇女节”）和公共假期。
- 假期数据：主要国际意识日和美国/英国/欧盟公共假期的捆绑数据集。随着每个平台版本的更新。
- 用户可以打开/关闭叠加。
- 用户可以将自定义事件添加到日历（工作区范围） - 例如，“客户端产品启动”或“活动开始”。
- 自定义事件在日历上显示为全角栏，类似于 Google 日历中的全天事件。

**跨工作空间日历（组织级别）：**
- 组织管理员和所有者可从组织仪表板访问。
- 在单个日历视图中显示所有工作区的计划/发布的帖子。
- 帖子按工作区进行颜色编码（工作区颜色来自 F-1.2 设置）。
- 只读 - 单击帖子可导航到特定工作区的日历。
- 可按工作区过滤（多选）。

**空状态：**
- 当工作区没有帖子（没有草稿、没有计划、没有发布）时，日历显示居中的空状态：
  - 插图：带有“+”符号的简单日历图标。
- 标题：“尚未安排内容。”
  - 正文：“创建您的第一篇帖子以在日历上看到它。”
  - 主 CTA 按钮：“创建帖子”→ 打开编辑器 (F-2.1)。
  - 辅助文本链接：“或从 CSV 导入”→ 打开批量导入对话框。
- 当过滤器处于活动状态但未产生任何结果时，日历会显示：“没有帖子与您的过滤器匹配。”带有“清除过滤器”按钮。

### 数据模型
- `PostingSlot`：id、social_account_id、day_of_week（整数，0-6）、时间（没有时区的时间）、is_active（布尔值）。
- `Queue`：id、workspace_id、名称、category_id、social_account_id、created_at、updated_at。
- `QueueEntry`：id、queue_id、post_id、位置（整数）、分配的槽位日期时间（日期时间）、创建时间。
- `CustomCalendarEvent`：id、workspace_id、标题、描述、start_date、end_date、颜色（十六进制）、created_by、created_at。
- `RecurrenceRule`：id、post_id、频率（枚举：每日、每周、每月）、间隔（整数）、end_date（可为空）、last_generate_at（日期时间）。

### 依赖关系
- F-2.1（作曲家）-后期创作和编辑。
- F-2.2（审批工作流程）- 状态过滤和发布状态。
- F-2.4（发布引擎）- 在预定时间发布帖子。
- F-4.1（分析）- 最佳时间计算。
- F-1.3 (RBAC) - 拖放权限。

### 验收标准
- 对于可见月份内有 200 个预定帖子的工作区，月视图可在 2 秒内加载。
- 将帖子拖到新时间会更新 Scheduled_at 值，并且日历会立即反映更改（乐观的 UI 更新）。
- 批量导入500行CSV可在60秒内完成处理（不包括媒体下载时间）。
- 基于队列的调度将帖子分配到正确的下一个可用插槽并实时更新队列顺序视图。
- 定期生成后作业会在创建规则后 5 秒内创建接下来 90 天的帖子。
- 跨工作空间日历以不同的颜色正确显示来自 50 个工作空间的帖子。

## F-2.4 - 发布引擎

### 目的
后端系统负责在预定时间向社交媒体平台发送帖子。处理 API 通信、速率限制、重试逻辑、媒体处理和状态报告。

### 用户故事
- 作为用户，我的预定帖子会在正确的时间在正确的平台上发布。
- 作为用户，如果帖子无法发布，我会收到通知并可以看到错误原因。
- 作为用户，第一条评论会在主帖子之后自动发布。
- 作为自托管管理员，我可以查看所有发布尝试的日志以进行调试。

### 功能要求

**调度与调度：**
- 后台工作进程连续运行，检查 `scheduled_at <= now()` 和 `status = 'scheduled'` 的帖子。
- 轮询间隔：每 15 秒一次。
- 当帖子被选中时，其状态会更改为“发布”（以防止重复处理）。
- 对于与帖子关联的每个 PlatformPost，引擎将发布作业分派给适当的平台提供商。
- 多平台帖子并行（而非顺序）发布平台帖子。

**平台提供商：**
- 每个支持的平台都有一个专用的提供程序模块，用于实现标准提供程序接口。
- 提供商职责：OAuth 令牌管理（过期则刷新）、API 请求构造、媒体上传、响应解析、错误处理。

| 平台 | API | 身份验证方法 | 发布功能|
|----------|-----|-------------|----------------------|
| Facebook 页面 | 图表 API v21+ | OAuth 2.0（页面访问令牌） | 文本帖子、单图像、多图像（通过多照片轮播）、视频、链接帖子。故事。 |
| Instagram | Instagram Graph API（通过 Facebook） | OAuth 2.0（链接到 Facebook 页面的 Instagram 企业帐户） | 单张图像、轮播（最多 20 个项目）、卷轴（视频）、故事（图像或视频）。两步：创建容器→发布容器。 |
| LinkedIn | LinkedIn 营销 API v2 | OAuth 2.0（3 条腿） | 文本帖子、图片帖子（最多 20 张图片）、视频帖子、文章、民意调查、文档 (PDF)。简介和公司页面。 |
| TikTok | TikTok 内容发布 API | OAuth 2.0 | 视频帖子。需要视频上传→发布流程。直接发布或“收件箱”模式（用户从 TikTok 应用程序发布）。需要隐私级别设置。 |
| YouTube | YouTube 数据 API v3 | OAuth 2.0 (Google) | 视频上传，包含标题、说明、标签、类别、隐私状态、缩略图。通过宽高比+时长检测短片。 |
| Pinterest | Pinterest API v5 | OAuth 2.0 | Pins：带有标题的图像或视频，描述、链接、board_id。 |
| 线程 | 线程 API（通过 Instagram 图表 API） | OAuth 2.0（Instagram 业务）帐户）| 文本帖子、图片帖子、轮播（最多 20 条）、视频帖子。 |
| Bluesky | AT 协议 (XRPC) | 基于会话（句柄 + 应用程序密码） | 文本帖子 (300字符数限制）、图片帖子（最多 4 张图片）、视频帖子。带有构面的富文本（链接、提及、解析为构面的主题标签）。 |
| Google 商家资料 | Google 商家资料 API | OAuth 2.0 (Google) | 本地帖子： 什么新、活动、优惠。图片+文字。 |
| Mastodon | Mastodon API v1 | OAuth 2.0（按实例应用程序注册） |文本帖子（字符数限制因实例而异）、图像（最多 4 个）、视频、民意调查。内容警告。可见性：公开、非公开、私人、直接。 |

**媒体处理：**
- 在发布之前，引擎会处理媒体以满足平台要求：
  - 图像调整大小：如果图像超过平台的最大尺寸，则按比例调整大小。在媒体库中保留原件。
- 图像格式转换：对于不支持WebP的平台，将WebP转换为JPEG。如果文件大小超出平台限制，则将 PNG 转换为 JPEG。
  - 视频转码：如果视频的编解码器、比特率或容器格式不兼容，请使用 FFmpeg 进行转码。目标：H.264编解码器、AAC音频、MP4容器。
  - 缩略图生成：以 1 秒的速度提取视频缩略图的帧（如果没有上传自定义缩略图，则用于日历预览和 YouTube）。
- 媒体处理在预定发布时间之前异步完成。后台作业处理媒体以发布安排在下一小时内的帖子。
- 如果媒体处理失败，帖子将被标记为“失败”，并显示错误“媒体处理失败：[原因]”，并通知作者。

**第一条评论：**
- 主帖成功发布并收到 platform_post_id 后，引擎使用平台评论 API 发布第一条评论。
- 延迟：主要帖子发布和第一个评论之间等待 5 秒（某些平台将立即评论标记为垃圾邮件）。
- 支持的首次评论平台：Instagram（评论自己的媒体）、Facebook Pages（评论自己的帖子）、LinkedIn（评论自己的帖子）、YouTube（评论自己的视频）。
- 如果第一个评论失败，主帖仍被视为“已发布”。第一次评论失败会单独记录并通知作者。

**速率限制管理：**
- 每个平台提供商根据 API 响应标头跟踪自己的速率限制。
- 速率限制状态按社交帐户存储（不是全局），因为限制通常是按帐户进行的。
- 已知限制：
  - Instagram：每个帐户每 24 小时滚动窗口发布 100 个 API 帖子。每个帐户每小时 200 API 次调用。
  - Facebook：每个用户令牌每小时 200 次 API 次调用。每页每 24 小时有 4,800 个帖子。
  - LinkedIn：每位会员每天拨打 100 次 API 次来发帖。公司页面：每天 100 股。
  - TikTok：因应用程序审核级别而异。默认：每天 5 个视频。
  - YouTube：每天 10,000 个配额单位（视频上传 = 1,600 个单位）。
  - Pinterest：每小时 1,000 个 API 次调用。
  - Bluesky：每个帐户每小时 5,000 次操作，每天 35,000 次。
- 乳齿象：因实例而异。典型：每 3 小时 300 个帖子。
- 如果发布尝试达到速率限制，则该帖子将在速率限制窗口重置后排队等待重试。
- 系统在尝试发布之前主动检查速率限制余量。如果剩余配额不足，发帖会被延迟，并且作者会受到警告。

**重试逻辑：**
- 如果发布尝试失败（API 错误、网络超时、服务器错误），引擎将使用指数退避重试：
  - 重试 1：1 分钟后。
  - 重试 2：5 分钟后。
  - 重试 3：30 分钟后。
- 重试 3 次失败后，PlatformPost 被标记为“失败”，并显示上次尝试的错误消息。
- 如果多平台帖子在某些平台上成功而在其他平台上失败，则整体帖子状态为“partially_published”。每个 PlatformPost 都有自己的状态。
- 失败的 PlatformPosts 可以由作者从日历或帖子详细信息视图中手动重试（“重试”按钮）。

**发布日志：**
- 每次发布尝试（包括重试）都会记录：时间戳、social_account_id、platform_post_id（如果收到）、HTTP 状态代码、响应正文（截断为 1,000 个字符）、错误消息（如果有）、持续时间（毫秒）。
- 可在帖子详细信息视图中查看每个帖子的发布日志（经理+角色可访问）。
- 日志保留 90 天，然后通过清理作业删除。

**令牌刷新：**
- 后台作业每小时运行一次，以检查所有在接下来的 24 小时内到期的 OAuth 令牌。
- 使用平台的刷新令牌流程刷新过期令牌。
- 如果刷新失败（例如，用户撤销访问权限），社交帐户将被标记为“已断开连接”，并通知工作区管理员。
- 具有不可刷新令牌的平台（Bluesky 应用程序密码不会过期；Mastodon 令牌默认不会过期）将被跳过。

**发布后操作：**
- 成功发布后，引擎：
  1. 将 platform_post_id 存储在 PlatformPost 记录中。
  2. 将PlatformPost状态更新为“已发布”并设置published_at。
  3. 如果某个帖子的所有 PlatformPost 均已发布，则将帖子状态更新为“已发布”。
  4. 触发帖子的第一次分析获取（计划在发布后 1 小时内）。
5. 向作者发送通知（“您的帖子已发布在[平台]上”）。

### 数据模型
- `PublishLog`：id、platform_post_id（FK）、attempt_number（整数）、status_code（整数，可为空）、response_body（文本、截断）、error_message（文本、可为空）、duration_ms（整数）、created_at。
- `RateLimitState`：id、social_account_id、平台、requests_remaining（整数）、window_resets_at（日期时间）、last_updated。

### 依赖关系
- F-1.5（平台 API 凭证） - API 用于平台访问的密钥。
- F-2.1（作曲家） - Post 和 PlatformPost 实体。
- F-2.3（日历）- 调度时间戳。
- F-6.1（媒体库）- 用于上传的媒体资产。
- F-7.1（通知）- 发布成功/失败通知。
- F-4.1（分析）- 发布后触发第一个指标获取。

### 验收标准
- 计划于下午 2:00:00 PM 发布的帖子将在该时间后 30 秒内发布（截至下午 2:00:30）。
- 多平台帖子（Instagram + LinkedIn + Facebook）同时发布到所有 3 个平台；总时间不超过最慢平台+10秒。
- 如果达到 Instagram 速率限制，帖子将在窗口重置后排队重试； 1 分钟内通知作者。
- 重试 3 次失败后，该帖子将显示“失败”状态，并带有人类可读的错误消息和“重试”按钮。
- 1分钟1080p视频的视频转码在60秒内完成。
- 主帖发布后 10 秒内发布第一条评论。
- 令牌刷新作业在令牌过期前成功刷新令牌；没有帖子因令牌过期而失败。

## F-2.5 - 社交帐户连接

### 目的
将社交媒体帐户连接到工作区，以便平台可以代表用户发布内容并读取参与数据。

### 用户故事
- 作为工作区经理，我可以将客户的 Instagram Business 帐户连接到此工作区。
- 作为用户，我可以查看哪些帐户已连接、其状态，并在需要时重新连接。
- 作为用户，我希望连接过程就像单击“连接”并完成平台的 OAuth 流程一样简单。

### 功能要求

**连接流程：**
- 在工作区设置→“社交帐户”中，用户会看到受支持平台的网格，每个平台都有一个“连接”按钮。
- 单击“连接”启动平台的 OAuth 流程：
  1. 用户被重定向至平台授权页面。
  2.用户授予权限。
  3. 用户将被重定向回带有授权码的应用程序。
  4.应用程序将代码交换为访问+刷新令牌。
  5. 应用程序获取帐户个人资料（姓名、头像、关注者数量）并存储。
  6. 该帐户将显示在工作区的已连接帐户列表中。
- 对于一个 OAuth 流程授予对多个帐户的访问权限的平台（例如，Facebook OAuth 授予对多个页面的访问权限），OAuth 后会向用户显示一个选择屏幕，以选择连接到此工作区的特定 account(s)。
- 对于 Bluesky：用户输入其句柄（例如 user.bsky.social）和应用程序密码（在 Bluesky 设置中生成），而不是 OAuth。系统创建一个会话。
- 对于 Mastodon：用户输入其实例 URL（例如，mastodon.social）。系统会在该实例上自动注册 OAuth 应用程序，然后继续使用标准 OAuth。

**连接帐户显示：**
- 每个连接的帐户显示：平台图标、帐户名称/句柄、头像、关注者计数（定期获取）、连接状态（已连接、令牌过期、已断开连接、错误）。
- 状态含义：
  - `connected`：正常工作。
  - `token_expiring`：令牌将在 7 天内过期，并且尚未尝试刷新。
  - `disconnected`：令牌无效且刷新失败。需要重新验证。
  - `error`：上次交互时出现 API 错误（带有错误消息）。

**重新连接：**
- 如果帐户断开连接，“重新连接”按钮会再次启动该特定帐户的 OAuth 流程。
- 重新连接会保留所有历史数据（帖子、分析） - 它只会更新 OAuth 令牌。

**断开连接：**
- 工作区所有者/管理员可以断开帐户。
- 断开连接会撤销 OAuth 令牌（如果平台的 API 支持撤销）并将帐户标记为已断开连接。
- 保留历史数据（发布的帖子、分析）。
- 针对此帐户的预定帖子已暂停，并通知团队。

**账户健康检查：**
- 后台作业每 6 小时通过轻量级 API 调用检查每个连接的帐户（例如，获取个人资料信息）。
- 如果检查失败，则会更新帐户状态并通知工作区管理员。

**所需权限（每个平台）：**

| 平台 | 所需权限/范围 |
|----------|-----------------------------|
| Facebook | Pages_manage_posts、pages_read_engagement、pages_read_user_content、pages_manage_metadata |
| Instagram | instagram_basic、instagram_content_publish、instagram_manage_comments、instagram_manage_insights |
| LinkedIn | w_member_social、r_member_social（个人资料）； w_organization_social、r_organization_social（公司页面）|
| 抖音 | user.info.basic、video.publish、video.upload |
| YouTube | youtube.upload、youtube.readonly、youtube.force-ssl |
| Pinterest | 板：读，引脚：读，引脚：写 |
| 线程 |threads_basic、threads_content_publish、threads_manage_insights、threads_manage_replies |
| Bluesky | 不适用（会话身份验证） |
| Google 商家资料 |business.manage |
| Mastodon | 读、写、跟随（标准范围） |

### 数据模型
- `SocialAccount`：id、workspace_id、platform（枚举）、account_platform_id（字符串 - 平台上帐户的 ID）、account_name（字符串）、account_handle（字符串，可为空）、avatar_url（字符串）、follower_count（整数）、oauth_access_token（加密）、oauth_refresh_token（加密）， token_expires_at（日期时间，可为空）、instance_url（字符串，可为空 - 对于 Mastodon）、connection_status（枚举：已连接、token_expiring、断开连接、错误）、last_health_check_at（日期时间）、last_error（文本、可为空）、connected_at（日期时间）。

### 依赖关系
- F-1.2（工作空间）- 帐户属于工作空间。
- F-1.5（平台 API 凭据）- OAuth 流的应用程序凭据。
- F-2.4（发布引擎）- 使用令牌进行发布。

### 验收标准
- 连接 Instagram Business 帐户可在 30 秒内完成（用户时间，不包括在 Instagram 授权页面上花费的时间）。
- 连接后，该帐户将显示在工作区中，并具有正确的名称、头像和关注者数量。
- 断开连接的帐户会显示清晰的“重新连接”按钮，并且不会丢失历史数据。
- 健康检查在 6 小时内检测到已撤销的令牌并通知经理。

## F-3.1 - 统一社交收件箱

### 目的
将工作区中所有连接帐户的所有入站参与（评论、提及、API 允许的 DM、评论）聚合到单个可管理的源中。允许团队成员无需离开平台即可做出响应。

### 用户故事
- 作为一名编辑，我可以在一个提要中查看所有关联帐户的所有评论和提及。
- 作为经理，我可以将对话分配给团队成员以进行响应。
- 作为编辑，我可以直接从收件箱回复评论，并在平台上本地发布回复。
- 作为经理，我可以使用保存的回复来快速回复常见问题。
- 作为经理，我可以查看我的团队的响应时间指标。

### 功能要求

**收件箱提要：**
- 默认视图：所有入站消息按时间顺序排列，最新的在前。
- 每条消息显示：平台图标、收到的帐户名称、发件人姓名/句柄、发件人头像、消息文本、时间戳、消息类型徽章（评论、提及、私信、评论）、情绪徽章（正面/中立/负面）、分配状态。
- 消息按适用的对话线程分组（例如，对特定帖子的评论线程的所有回复都分组在该帖子下）。
- 单击消息可将其展开以显示完整的对话上下文（原始帖子、家长评论、线程中的所有回复）。

**消息类型：**

| 类型 | 平台 | API 来源 |
|------|-----------|-----------|
| 评论 | Instagram、Facebook、LinkedIn、YouTube、TikTok（只读）、Pinterest、Threads、Bluesky、Mastodon | 平台评论/回复 API |
| 提及 | Instagram、Facebook、LinkedIn、Mastodon、Bluesky | 提及/标记 API |
| DM | Instagram（具有批准权限的企业帐户）、Facebook 页面（页面对话） | 消息 API |
| 评价 | Google 商家资料 | GBP 评价 API |

- 对于 DM 访问需要提升权限或不可用的平台（LinkedIn、TikTok、Pinterest、YouTube、Threads、Bluesky），不显示 DM 消息类型。

**过滤：**
- 按平台：多选复选框。
- 按社交帐户：多选下拉列表（如果工作区在同一平台上有多个帐户，则很有用）。
- 按消息类型：评论、提及、DM、评论。
- 按状态：未读、打开、已解决、已存档。多选。
- 按指定的团队成员：下拉列表包括“未指定”。
- 按情绪：积极、中立、消极。
- 按日期范围。
- 跨消息内容的自由文本搜索。

**作业：**
- 任何具有收件箱访问权限的工作区成员（编辑+角色）都可以将消息分配给特定的团队成员。
- 分配：单击消息上的头像/姓名缩写栏 → 从下拉列表中选择团队成员。
- 分配的消息显示在受让人的“我的队列”视图中。
- 未分配的消息出现在“未分配”队列中。
- 分配会触发对受让人的通知。

**回复：**
- 单击任何消息上的“回复”即可在对话线程底部打开回复编辑器。
- 回复文本通过平台的API提交，并在平台上显示为原生回复。
- 回复编辑器显示：文本输入、字符限制（如果适用）、附加图像的选项（在支持图像回复的平台上）。
- 回复后，消息状态自动更改为“已解决”（可配置：回复时自动解决，或需要手动解决）。

**保存的回复：**
- 预先编写的响应模板的工作区级库。
- 每个保存的回复都有：标题（用于搜索）、正文、可选的个性化变量：`{sender_name}`、`{account_name}`、`{post_url}`。
- 插入已保存的回复会填充回复编辑器。用户可以在发送前进行编辑。
- 保存的回复在工作区设置中进行管理。

**内部注释：**
- 在任何消息上，团队成员都可以添加内部注释（文本，仅团队可见，不公开发布）。
- 内部注释以独特的视觉风格出现在对话线程中（例如黄色背景、“内部”徽章）。
- 用例：“客户表示不要对此做出回应”或“升级至客户经理”。

**情绪分析：**
- 每条传入消息都会自动标记情绪：积极、中立或消极。
- 情绪由基于关键字的规则引擎（每个工作区可配置的正面/负面关键字列表）确定，如果配置了 AI 密钥 (8800000000000000888)，则可以选择基于 AI 的情绪分析。
- 情绪标签是可编辑的 - 团队成员可以手动覆盖自动检测到的情绪。
- 情绪用于过滤并包含在分析/报告中。

**批量操作：**
- 选择多条消息（复选框）并且：
  - 标记为已读。
  - 标记为已解决。
  - 存档。
  - 分配给团队成员。
- 2 秒内处理最多 50 条选定消息的批量操作。

**SLA 定时器（可选）：**
- 每个工作区可以配置目标响应时间（例如“2 小时内响应”）。
- 如果超过 SLA，未解决的消息会显示倒计时或“逾期”徽章。
- 分析 (F-4.2) 中有 SLA 个指标（平均响应时间、SLA 合规率）。

**收件箱同步：**
- 后台作业每 5 分钟同步来自每个连接帐户的消息。
- 对于支持 webhook 的平台（通过 webhook 订阅的 Facebook、Instagram），使用实时消息传递而不是轮询。
- 新消息触发通知（应用内徽章计数更新、可选电子邮件/Slack 通知）。
- 同步会在每次轮询中检索过去 24 小时内的消息。重复数据删除可确保消息不重复。

**空状态：**
- 当收件箱有零条消息时（没有连接社交帐户或尚未参与）：
  - 插图：语音气泡图标。
  - 标题：“您的收件箱是空的。”
  - 正文：“来自您关联帐户的评论、提及和私信将显示在此处。”
  - 如果没有连接社交帐户：CTA按钮“连接帐户”→打开社交帐户连接流程（F-2.5）。
  - 如果帐户已连接但还没有消息：信息文本“消息每 5 分钟同步一次。新的参与将自动出现。”
- 当过滤器处于活动状态但未产生任何结果时：“没有消息与您的过滤器匹配。”带有“清除过滤器”按钮。

### 数据模型
- `InboxMessage`：id、workspace_id、social_account_id、platform_message_id（字符串，每个平台唯一）、message_type（枚举：评论、提及、DM、评论）、sender_name、sender_handle、sender_avatar_url、正文（文本）、情绪（枚举：积极、中性、消极）、情绪_源（枚举：自动、手动）、状态（枚举：未读、打开、已解决、已存档）、signed_to（user_id、可为空）、parent_message_id（可为空，对于线程）、related_post_id（可为空 - 如果消息是对我们帖子的评论，则链接到 PlatformPost）、received_at（日期时间）、created_at。
- `InboxReply`：id、inbox_message_id、author_id（回复的团队成员）、正文（文本）、platform_reply_id（字符串 - 来自 API）、sent_at（日期时间）。
- `InternalNote`：id、inbox_message_id、author_id、正文（文本）、created_at。
- `SavedReply`：id、workspace_id、标题、正文（文本）、created_by、created_at、updated_at。
- `InboxSLAConfig`：id、workspace_id、target_response_分钟（整数）、is_active（布尔值）。

### 依赖关系
- F-2.5（社交帐户连接）- 用于消息同步的连接帐户。
- F-1.3 (RBAC) - 收件箱访问权限。
- F-5.3（AI 集成）- 可选的基于 AI 的情绪分析。
- F-7.1（通知）- 新消息和分配通知。
- F-4.2（跨账户分析） - SLA 指标。

### 验收标准
- 连接的 Instagram 帖子上的新评论会在 5 分钟（投票）或 30 秒（网络钩子）内出现在收件箱中。
- 从收件箱回复 Instagram 评论会在 5 秒内将回复发布到 Instagram 上。
- 保存的回复变量 `{sender_name}` 在插入之前替换为实际发件人姓名。
- 情绪自动标记在同步时进行，不会延迟消息显示。
- SLA 计时器从配置的目标准确倒计时，超出时显示“逾期”。

## F-4.1 - 每个帐户分析

### 目的
为每个连接的社交帐户提供来自平台 API 的参与度和增长指标。数据会自动收集并显示在每个工作区的仪表板中。

### 用户故事
- 作为经理，我可以查看每个关联帐户的关注者增长、参与率和覆盖趋势。
- 作为编辑，我可以看到我的哪些帖子表现最好。
- 作为经理，我可以根据历史数据确定发布的最佳时间。

### 功能要求

**收集的指标：**

| 公制 | 平台 | 收集频率 |
|--------|-----------|---------------------|
| 关注者/订阅者数量 | 全部 | 每日 |
| 关注者增长（净变化） | 全部 | 根据每日快照计算 |
| 帖子展示次数 | Instagram、Facebook、LinkedIn、Pinterest、YouTube、Threads、Bluesky、Google Business | 前 48 小时每小时一次，然后每天 |
| 帖子到达率 | Instagram、Facebook、LinkedIn、话题 | 前 48 小时每小时一次，然后每天 |
| 帖子互动（点赞、评论、分享、保存、点击） | 全部 | 前 48 小时每小时，然后每天 |
| 视频观看次数 | Instagram (Reels)、Facebook、YouTube、TikTok、Pinterest、LinkedIn | 前 48 小时每小时一次，然后每天 |
| 视频观看时长 | YouTube、TikTok | 每日 8800000000000003888
| 参与率 | 全部（计算得出） | 计算得出：（总参与度/覆盖面）× 100。如果覆盖面不可用，请使用展示次数。 |
| 个人资料浏览量 | Instagram、TikTok（如果有） | 每日 |
| 网站点击量 | Instagram、LinkedIn、Pinterest、Google Business | 每日 |
| 受众人口统计 | Instagram、Facebook、YouTube、LinkedIn（公司页面）、TikTok | 每周 |

**分析仪表板（每个工作区、每个帐户）：**

*概览卡：*
- 选定日期范围的顶级指标（默认：过去 30 天）：总展示次数、总覆盖面、总参与度、平均参与率、关注者数量（当前）、关注者变化（增量）。
- 比较：显示与前一时期相同长度的百分比变化。

*关注者增长图：*
- 显示随时间变化的关注者数量的折线图。
- 日期范围选择器：7 天、30 天、90 天、12 个月、自定义。
- 悬停时的工具提示显示准确的计数和日期。

*随时间变化的参与度图表：*
- 堆积条形图或折线图显示按类型（点赞、评论、分享、保存）细分的每日参与度。
- 相同的日期范围选择器。

*表现最佳的帖子：*
- 按参与率（或可选择：按覆盖范围、按印象数、按总参与度）排名的帖子的表格/卡片视图。
- 显示：帖子缩略图、标题片段、发布日期、平台和选定的指标值。
- 可按内容类别、日期范围、平台进行过滤。
- 默认前10名，可扩展至50名。

*发布热图的最佳时间：*
- 7×24 网格（一周中的天数 × 一天中的小时数）显示每个时间段内发布的帖子的平均参与率。
- 从低（冷）到高（暖）参与度的颜色渐变。
- 基于过去 90 天的数据。
- 最小数据阈值：数据点少于 3 个的单元格会变灰，并显示“数据不足”工具提示。

*观众人口统计（如有）：*
- 饼图或条形图：年龄范围、性别分布、热门国家/地区、热门城市。
- 数据来源：平台提供的受众洞察API。
- 每周更新。

**数据收集引擎：**
- 后台作业从每个平台的 API 获取分析数据。
- 时间表：
  - 对于过去 48 小时内发布的帖子：每小时获取一次指标。
  - 对于 2-30 天前发布的帖子：每天获取指标。
  - 对于 30 多天前发布的帖子：不再收集（保留最终快照）。
  - 帐户级指标（关注者、人口统计）：每天获取。
- 数据存储为时间序列快照（请参阅数据模型）。
- 如果 API 调用失败，则会在下一次计划运行时重试。

**数据保留：**
- 所有收集的分析数据都将无限期保留（云和自托管）。

**空状态：**
- 当帐户还没有分析数据时（新连接，没有发布帖子）：
  - 插图：带有占位线的条形图图标。
  - 标题：“尚无分析数据。”
  - 正文：“发布您的第一篇帖子，分析将开始自动收集。初始指标将在发布后 1 小时内显示。”
  - CTA 按钮：“创建帖子”→ 打开编辑器 (F-2.1)。
- 当工作区没有连接的社交帐户时：
  - 标题：“连接帐户以查看分析。”
  - CTA按钮：“连接帐户”→打开社交帐户连接流程（F-2.5）。
- 单个图表为空状态：如果特定图表数据不足（例如，热图的数据点少于 3 个），图表区域会显示一个占位符，其中显示“没有足够的数据来显示此图表。发布更多内容并稍后再回来查看。”

### 数据模型
- `AnalyticsSnapshot`：id、platform_post_id（FK 到 PlatformPost）、展示次数（整数）、覆盖范围（整数）、喜欢（整数）、评论（整数）、分享（整数）、保存（整数）、点击（整数）、video_views（整数，可为空）、engagement_rate（小数）、snapshot_at （日期时间）。
- `AccountMetricsSnapshot`：id、social_account_id、follower_count（整数）、following_count（整数）、post_count（整数）、profile_views（整数、可为空）、website_clicks（整数、可为空）、snapshot_at（日期时间）。
- `AudienceDemographics`：id、social_account_id、age_ranges (json)、gender_split (json)、top_countries (json)、top_cities (json)、snapshot_at (datetime)。

### 依赖关系
- F-2.4（发布引擎）- 发布后触发第一次分析获取。
- F-2.5（社交帐户连接）- 用于 API 访问的连接帐户和令牌。

### 验收标准
- 3 秒内加载 500 个帖子的帐户的分析仪表板。
- 粉丝增长图表准确反映每日净变化。
- 最佳时间热图正确识别参与度最高的时间段。
- 数据收集作业可以优雅地处理 API 个速率限制（退出并重试）。

## F-4.2 - 跨账户和跨工作空间分析

### 目的
组织级仪表板让机构所有者一目了然地了解所有客户的健康状况、比较绩效并跟踪团队生产力。

### 用户故事
- 作为组织管理员，我可以看到哪些工作区表现良好以及哪些工作区需要关注。
- 作为经理，我可以查看团队的平均审批周转时间和收件箱响应时间。
- 作为组织管理员，我可以比较所有客户的参与率。

### 功能要求

**组织仪表板：**

*客户健康概况：*
- 卡片网格显示每个工作区：工作区名称、图标、发布的帖子总数（本月）、平均参与率（本月）、关注者增长增量（本月）、待批准计数、失败帖子计数。
- 颜色编码的健康指示器：绿色（高于平均水平）、黄色（平均）、红色（低于平均水平或存在问题）。
- “低于平均水平”的定义是低于组织中所有工作空间的参与率中位数。

*跨工作空间比较表：*
- 包含列的可排序表格：工作区名称、platform(s)、发布的帖子、展示次数、覆盖范围、参与率、关注者增长、平均响应时间（收件箱）。
- 日期范围选择器（默认：当前月份）。
- 导出为 CSV。

*团队绩效指标：*
- 组织成员表，其中包含：姓名、创建的帖子（计数）、平均审批周转时间（“pending_review”和“approved”之间的小时数）、平均收件箱响应时间（收到消息和第一次回复之间的分钟数）、收件箱中当前分配的帖子。
- 日期范围选择器。
- 可按工作区过滤。

**警报：**
- 组织级别的可配置警报：
  - “[工作空间] 的参与率降至 [阈值]% 以下。”每个工作区的阈值都是可配置的。
  - “过去 [N] 天内没有发布关于 [工作区] 的帖子。” N 是可配置的。
  - “过去 24 小时内，所有工作区中的 [N] 个帖子都失败了。”
- 通过应用内通知和电子邮件发送给组织管理员的警报。

### 数据模型
- 跨工作空间分析是通过使用工作空间级别聚合查询每个工作空间数据 (F-4.1) 来即时计算的。无需单独存储。
- 团队绩效指标查询：PostVersion（批准时间戳）、InboxMessage（响应时间戳）。
- `OrgAlert`：id、organization_id、alert_type（枚举）、workspace_id（可为空）、threshold_value、is_active（布尔值）。

### 依赖关系
- F-4.1（每个账户分析）- 源数据。
- F-3.1（收件箱）- 响应时间数据。
- F-2.2（审批工作流程）- 审批周转数据。
- F-7.1（通知）- 警报传送。

### 验收标准
- 对于拥有 50 个工作区的组织，组织仪表板可在 5 秒内加载。
- 跨工作空间比较 CSV 导出包括所有可见列并遵循所选日期范围。
- 团队绩效准确计算平均审批周转时间（根据 10 个样本帖子的手动计算进行验证）。

## F-4.3 - 报告生成器

### 目的
生成品牌 PDF 报告以供客户交付。报告将分析数据、评论和可视化结合到专业文档中，机构可以与客户共享。

### 用户故事
- 作为经理，我可以在 5 分钟内为我的客户创建每月绩效报告。
- 作为经理，我可以使用我机构的品牌对报告进行白标。
- 作为经理，我可以安排每月自动生成报告并通过电子邮件发送给我的客户。
- 作为客户，我可以查看和下载与我共享的报告。

### 功能要求

**报告创建：**
- 工作区分析部分中的“创建报告”按钮。
- 第 1 步：选择模板或从头开始。
- 第 2 步：配置报告参数：标题、日期范围、要包含的社交帐户、要包含的内容类别。
- 第 3 步：报告编辑器 - 用于排列报告部分的拖放编辑器。

**报告部分（构建块）：**

| 部分类型 | 内容 |
|-------------|---------|
| 封面 | 报告标题、日期范围、工作区徽标（或机构徽标，如果有白色标签）、生成日期。 |
| 执行摘要 | 用户在其中编写手动摘要/注释的文本块。支持基本的富文本（粗体、斜体、项目符号）。 |
| 关键指标 | 一行指标卡（展示次数、覆盖面、参与度、参与率、关注者增长），并进行同期比较。用户选择要显示的指标。 |
| 关注者增长图表 | F-4.1 的折线图。用户选择要包含的帐户。 |
| 参与度细分图表 | 日期范围内按类型划分的参与度条形图。 |
| 表现最佳的帖子 | 前 N 个帖子的网格，包含缩略图、标题和指标。 N 是可配置的（默认值：5）。 |
| 最佳时间热图 | 来自 F-4.1 的热图。 |
| 平台细分 | 显示按平台划分的指标的饼图或表格。 |
| 内容类别性能 | 显示每个内容类别指标的表格或图表。 |
| 自定义文本 | 用于附加注释的自由格式文本块。 |
| 受众人口统计数据 | 来自 F-4.1 的饼图/条形图。 |

- 可以通过拖动来重新排序部分。
- 可以添加或删除部分。
- 每个部分都有一个切换按钮，可以将其包含在最终报告中/从最终报告中排除。

**模板：**
- 预建模板：“每月概览”、“活动报告”、“季度回顾”。
- 用户可以将报告配置保存为自定义模板以供重复使用。
- 模板存储：包含哪些部分、它们的顺序和默认指标选择。数据不被存储——它是在生成时新鲜获取的。

**白标品牌：**
- 如果配置了白标签 (F-5.2)，则报告使用：机构徽标（在页眉和封面页中）、机构颜色（用于图表强调和部分标题）、机构名称和联系信息（在页脚中）。
- 如果未配置白标签，报告将使用平台的默认品牌。
- 如果白标处于活动状态，则永远不会显示平台自己的品牌。

**生成和导出：**
- “生成报告”按钮生成渲染报告。
- 预览：报表在预览窗格中呈现为 HTML。
- 导出选项：下载为PDF，下载原始数据为CSV。
- PDF 生成：使用 WeasyPrint 进行服务器端渲染（Python 原生 HTML-to-PDF 库）。图表预先渲染为 SVG 图像，并在 PDF 转换之前嵌入到 HTML 模板中。选择 WeasyPrint 而不是无头浏览器解决方案（Playwright、Puppeteer），因为它不添加外部二进制依赖项，保持 Docker 映像较小，并与 Django 模板本机集成。 CSS 限制（WeasyPrint 中没有 Flexbox/网格）仅通过在报告模板中使用基于表格和基于浮动的布局来处理。如果事实证明 WeasyPrint 的 CSS 支持不足以支持未来迭代中的复杂布局，则可以使用到无头浏览器渲染器的迁移路径，但在启动时不需要。

**预定报告：**
- 用户可以将报告配置为按计划自动生成：每周（每周一）、每两周、每月（每月 1 日）。
- 在计划日期，系统生成包含配置日期范围内最新数据的报告（例如，“最近 30 天”始终相对于生成日期）。
- 生成的报告通过电子邮件发送给配置的收件人（工作区成员和/或客户电子邮件地址）。
- 电子邮件主题和正文是可配置的。默认主题：“[工作区名称] - [报告标题] - [日期范围]。”

**可分享链接：**
- 每个生成的报告都可以通过 URL 共享。
- URL 将报表呈现为只读网页（与预览相同的 HTML）。
- 访问控制：可选择密码保护。 （可选）设置一个到期日期，链接在该日期之后将停止工作。
- 可共享链接列在客户端门户 (F-1.4) 中。

### 数据模型
- `Report`：id、workspace_id、title、date_range_start、date_range_end、social_account_ids（json 数组）、category_ids（json 数组）、sections（json - 节配置的有序列表）、template_id（可为空）、created_by、created_at、updated_at。
- `ReportGeneration`：id、report_id、generate_at、pdf_url（字符串 - 存储的文件路径/URL）、html_url（字符串）、share_token（字符串、唯一）、share_password_hash（可为空）、share_expires_at（日期时间、可为空）。
- `ReportSchedule`：id、report_id、频率（枚举：每周、每两周、每月）、收件人（电子邮件的 json 数组）、email_subject、email_body、next_run_at（日期时间）、is_active（布尔值）。

### 依赖关系
- F-4.1（分析）- 所有报告部分的数据源。
- F-5.2（白标）- 报告品牌。
- F-1.4（客户门户）- 客户可见的报告。
- F-7.1（通知）- 预定的报告交付。

### 验收标准
- 生成包含 5 个部分的 30 天报告，可在 10 秒内完成。
- PDF 输出格式良好，没有视觉伪影、正确的图表和正确的白标品牌。
- 计划报告会在计划时间后 1 小时内按照配置的计划生成并通过电子邮件发送。
- 带密码的共享链接将拒绝没有正确密码的访问。
- 共享链接过期的报告会显示“此链接已过期”页面。

## F-5.1 - 身份验证和用户帐户

### 目的
用户注册、登录和会话管理。支持电子邮件/密码、社交 OAuth 登录和客户端魔术链接。

### 用户故事
- 作为新用户，我可以使用电子邮件/密码或 Google/GitHub OAuth 进行注册。
- 作为返回用户，我可以登录并进入我上次使用的工作区。
- 作为客户，我可以通过魔术链接访问该平台，无需密码。

### 功能要求

**注册：**
- 电子邮件+密码：电子邮件在整个平台上必须是唯一的。密码最少：8 个字符，无其他复杂性要求。密码使用 bcrypt 进行哈希处理（成本因子 12）。
- OAuth 登录：Google 和 GitHub。首次 OAuth 登录时，会自动创建一个帐户。用户的姓名和头像是从 OAuth 配置文件中填充的。
- 注册后，会自动为用户创建一个组织 (F-1.1)，并具有合理的默认值 - 无需设置步骤或提示。如果用户被邀请加入现有组织，则不会创建新组织 - 他们会加入现有组织。

**登录：**
- 电子邮件+密码表格。
- “继续使用 Google”和“继续使用 GitHub”OAuth 按钮。
- “忘记密码”流程：输入电子邮件→接收密码重置链接（1小时后过期）→设置新密码。
- 成功登录后，用户将被重定向到上次使用的工作区。如果不存在工作区，他们会看到空的组织仪表板，并提示创建第一个工作区。

**会议：**
- 会话令牌存储为仅 HTTP、安全、SameSite=Lax cookie。
- 会话持续时间：30 天（滑动 - 根据每个请求刷新）。
- 用户可以从其帐户设置中查看和撤销活动会话（“活动会话”列表显示设备、IP、上次活动时间）。

**魔法链接（针对客户）：**
- 请参阅 F-1.4 了解完整的 magic link 规范。

**帐户设置（每个用户）：**
- 姓名、电子邮件、头像。
- 更改密码。
- 连接的 OAuth 提供商（链接/取消链接 Google、GitHub）。
- 通知首选项（请参阅 F-7.1）。
- 活跃会话。
- 两因素身份验证（TOTP 通过身份验证器应用程序）。

**双因素身份验证 (2FA)：**
- 可选。用户可以从帐户设置中启用基于 TOTP 的 2FA。
- 设置：使用验证器应用程序扫描二维码，输入确认码。
- 后续登录时，输入密码后，系统会提示用户输入 TOTP 代码。
- 恢复代码：2FA 设置期间生成的 10 个一次性使用代码。存储散列。
- 组织所有者可以为所有组织成员强制执行 2FA（可在组织设置中配置）。

### 数据模型
- `User`：id、电子邮件（唯一）、名称、avatar_url、password_hash（可为空 - 对于仅 OAuth 用户为空）、totp_secret（加密、可为空）、totp_recovery_codes（加密 json、可为空）、totp_enabled（布尔值）、created_at、updated_at。
- `OAuthConnection`：id、user_id、提供商（枚举：google、github）、provider_user_id、provider_email、created_at。
- `Session`：id、user_id、token_hash、device_info（字符串）、ip_address、last_active_at、created_at、expires_at。

### 依赖关系
- F-1.1（组织）- 注册期间创建组织。
- F-1.3 (RBAC) - 身份验证后分配的角色。
- F-1.4（客户端） - 魔术链接验证。

### 验收标准
- 使用电子邮件/密码注册可在 5 秒内完成。
- 使用 Google 的 OAuth 登录可重定向、验证用户并在 10 秒内将用户返回到应用程序。
- 2FA 设置生成有效的二维码并在 30 秒 TOTP 窗口内接受确认码。
- 过期的会话重定向到登录页面，没有错误。

## F-5.2 - 白标配置

### 目的
允许代理机构以自己的身份彻底重塑平台。配置后，代理机构的客户会看到代理机构的品牌，而不是平台的品牌。

### 用户故事
- 作为组织所有者，我可以上传我的机构的徽标并设置品牌颜色。
- 作为组织所有者，我可以将我的机构的子域指向该平台。
- 作为客户，我在登录页面、门户、报告和电子邮件上看到我机构的品牌。

### 功能要求

**品牌设置（组织级别）：**

| 设置 | 详细信息 |
|---------|--------|
| 机构徽标 | 图片上传（PNG、SVG、JPG）。最大 2MB。用于：侧边栏、登录页面、客户端门户页眉、报告页眉/页脚、电子邮件页眉。两种变体：完整徽标（水平）和图标（方形，用于网站图标和紧凑显示）。 |
| 原色 | 十六进制颜色代码。适用于：侧边栏强调、按钮、链接、图表强调、报告部分标题。 |
| 辅助颜色 | 十六进制颜色代码。适用于：悬停状态、辅助按钮、图表辅助颜色。 |
| 机构名称 | 文本。显示于：页面标题、电子邮件发件人姓名、报告页脚。 |
| 机构联系信息 | 电子邮件、电话、网站 URL。显示在：报告页脚、登录页页脚。 |
| 网站图标 | 图片上传（ICO、PNG、32x32 或 64x64）。替换浏览器选项卡中平台的图标。 |
| 登录页面 | 自定义背景图片（上传，最大 5MB），自定义欢迎文本（最多 200 个字符）。 |

**自定义域：**
- 机构可以配置自定义子域（例如，social.myagency.com）或完整自定义域。
- 设置流程：（1）代理商在设置中输入所需的域名，（2）系统提供DNS指令（CNAME记录指向平台域名），（3）代理商配置DNS，（4）系统验证DNS 分辨率，(5) SSL 证书是自动配置的（Let's Encrypt）。
- DNS验证：系统在域输入后72小时内每5分钟检查DNS。验证成功后，自定义域将被激活。
- 该组织的所有平台 URL 均在自定义域下提供服务。
- 默认平台 URL (app.platform.com/org/...) 重定向到自定义域（如果配置）。
- **扩展说明（云）：** 自定义域使用 Caddy 的按需 TLS，它在请求时提供证书。这对于单个 VPS 部署非常有效。如果云版本扩展到负载均衡器后面的多个实例，则所有 HTTPS 终止都必须通过单个 Caddy 实例（或由数据库/S3 支持的 Caddy `storage` 指令等共享证书存储）进行路由，以便按需 TLS 挑战成功。这是启动后扩展的问题，而不是启动阻碍因素 - 在需要水平扩展时记录迁移路径。

**电子邮件品牌：**
- 所有外发电子邮件（批准请求、魔术链接、报告交付、通知）均使用：
  - 标题中的机构徽标。
  - 机构名称作为发件人姓名。
- 回复地址：可配置（默认：设置中的机构联系电子邮件）。
  - 自定义电子邮件域（例如，notifications@myagency.com）：需要 DNS 设置（SPF、DKIM、DMARC 条记录）。设置中提供的说明。使用第三方电子邮件发送服务集成。
- 如果未设置自定义电子邮件域，则从平台默认域发送电子邮件，并以机构名称作为显示名称。

**白标范围：**
- 白标签适用于：客户端门户、登录页面、系统发送的所有电子邮件、所有报告、侧边栏徽标。
- 白标 NOT 适用于：机构自己的团队成员的内部仪表板（他们在完整的应用程序中看到平台品牌，但可以切换“作为客户端预览”以查看白标视图）。

### 数据模型
- `WhiteLabelConfig`：id、organization_id、agency_name、agency_logo_url、agency_icon_url、primary_color（十六进制字符串）、 secondary_color（十六进制字符串）、agency_email、agency_phone、agency_website、favicon_url、login_background_url、login_welcome_text、custom_domain（字符串，可为空）、custom_domain_verified （布尔值）、custom_email_domain（可为空）、custom_email_verified（布尔值）、created_at、updated_at。

### 依赖关系
- F-1.1（组织）- 白标是组织范围的。
- F-1.4（客户端）- 使用白色标签呈现。
- F-4.3（报告）- 报告使用白标品牌。
- F-7.1（通知）- 电子邮件使用白标品牌。

### 验收标准
- 上传徽标并设置颜色会立即反映在客户端门户中（无缓存延迟 > 5 秒）。
- 自定义域可在 DNS 传播后 10 分钟内使用有效的 CNAME 记录。
- SSL 证书在 DNS 验证后 5 分钟内自动配置。
- 访问白标门户的客户会看到对该平台自有品牌的零引用。
- 从平台发送的电子邮件在标题中使用机构名称和徽标。

## F-5.3 - 集成

### 目的
将平台连接到用于设计、媒体、通信、自动化和人工智能的外部工具。

### 用户故事
- 作为编辑，我可以从作曲家中打开 Canva，并将完成的设计带回到我的帖子中。
- 作为经理，我可以在 Slack 中接收批准通知。
- 作为编辑，我可以使用 AI 通过我组织的 OpenAI API 密钥生成字幕。
- 作为开发人员，我可以使用 REST API 以编程方式创建帖子。

### 功能要求

**设计与媒体整合：**

*画布：*
- 后期编辑器中的“Design in Canva”按钮 (F-2.1) 可通过 Canva Connect API（以前称为 Canva 按钮）打开 Canva 编辑器。
- 用户完成设计后，将生成的图像导出到平台并保存在工作区媒体库中。
- 支持的 Canva 导出格式：PNG、JPG。
- Canva 集成需要在组织级别配置 Canva API 密钥。
- **自托管注意：** Canva Connect API 需要通过 Canva 开发者计划批准。自托管者必须申请自己的 Canva 开发者访问权限 88000000000001888 并创建 Canva 集成以获得 API 凭证。此批准过程可能需要几天到几周的时间。平台应在自托管设置指南中清楚地记录这一点，并且在未配置 API 密钥时，Canva 集成 UI 应显示带有设置说明的帮助链接。

*Unsplash，Pexels，GIPHY：*
- 在作曲家的媒体选择器中，“库存媒体”选项卡提供对 Unsplash（照片）、Pexels（照片 + 视频）和 GIPHY（GIF）的搜索。
- 搜索结果显示缩略图网格。单击结果会将其添加到帖子并将其保存到工作区媒体库。
- 归属：Unsplash 和 Pexels 需要根据其许可证进行归属。平台自动附加标题注释（可配置：默认打开，可切换关闭）。
- API 个密钥：Unsplash 和 Pexels 需要在组织级别配置 API 个密钥（可用免费套餐）。 GIPHY 使用其公共测试密钥进行基本访问。

**通信集成：**

*松弛：*
- 每个工作区均可配置。连接 Slack 工作区并选择通知渠道。
- 可以触发 Slack 通知的事件（每个可切换）：提交审批的新帖子、批准的帖子、拒绝的帖子、发布的帖子、失败的帖子、新的收件箱消息、8800000000000000888 逾期。
- Slack 消息包括：事件描述、帖子预览（标题片段、缩略图）、平台中帖子的链接。
- 通过 Slack OAuth 连接（带有传入 webhooks 和 chat:write 范围的 Slack 应用程序）。

*电子邮件 (SMTP):*
- 自托管部署为所有出站电子邮件配置 SMTP 设置（主机、端口、用户名、密码、TLS）。
- 云版本使用平台的托管电子邮件服务。
- 电子邮件模板可自定义（HTML/文本）：邀请、魔术链接、批准请求、报告传送、密码重置。

**人工智能集成：**

- 可在组织级别配置。设置页面：组织→设置→“AI 提供商”。
- 三个受支持的提供程序，每个提供程序独立配置。用户可以同时配置一项、两项或全部三项。其中一个被指定为默认值。

| 提供商 | 配置字段 |
|----------|---------------------|
| OpenAI | API key，默认型号（下拉列表：gpt-4o、gpt-4o-mini、gpt-4.1、gpt-4.1-mini、gpt-4.1-nano、o3-mini 或自定义型号 ID字符串）|
| Anthropic | API 键，默认模型（下拉列表：claude-sonnet-4-20250514、claude-haiku-4-5-20251001 或自定义模型 ID 字符串） |
| OpenRouter | API key，默认模型（文本字段 - OpenRouter 提供对数百个模型的访问，因此这是一个自由文本模型标识符，例如“anthropic/claude-sonnet-4”， “google/gemini-2.5-pro”、“meta-llama/llama-4-maverick”）。 “浏览模型”链接会在新选项卡中打开 OpenRouter 的模型目录以供参考。 |

- **默认提供程序设置：** AI 设置页面顶部的下拉菜单可以选择从编辑器或收件箱调用 AI 功能时默认的提供程序。选项：OpenAI、Anthropic 或 OpenRouter（只有配置了 API 密钥的提供商才会出现在下拉列表中）。
- **测试连接：** 每个提供商都有一个“测试”按钮，用于发送简单的提示（“回复确定”）并验证 API 密钥和模型是否正常工作。显示成功并显示模型名称和响应延迟，或显示失败并显示错误消息。
- **Composer 中的每代模型覆盖（请参阅 F-2.1）：** 当用户触发 Composer 中的任何 AI 操作时，AI 面板中会出现一个小的提供程序/模型选择器，允许他们覆盖该特定代的默认设置。这不会更改组织范围内的默认设置。
- 整个平台的人工智能功能（作曲家人工智能辅助、收件箱中的情绪分析）使用默认提供程序，除非被覆盖。
- 如果未配置 AI 提供程序，AI 功能将显示为灰色状态，并带有工具提示：“在组织设置中配置 AI 提供程序以启用此功能。”
- 无人工智能使用限制或积分 - 使用仅受用户自己的每个提供商的 API 密钥配额限制。
- API 个密钥静态加密存储 (AES-256-GCM)，加密方法与平台凭证相同。

**自动化（REST API 和 Webhooks）：**

*REST API:*
- 完整 CRUD API 用于：组织（读取）、工作区（读取）、帖子（创建、读取、更新、删除）、社交帐户（读取）、分析（读取）、收件箱消息（读取、回复）、媒体（上传、读取）、报告（生成、读取）。
- 身份验证：范围为组织的 API 个密钥（不记名令牌）。密钥在组织设置中创建/撤销。
- 每个 API 密钥都有一个可配置范围：“完全访问”或仅限于特定资源（例如，“帖子：读/写，分析：只读”）。
- 速率限制：每个 API 个密钥每小时 1,000 个请求。可配置为自托管。
- API 文档：自动生成的 OpenAPI/Swagger 规范位于 /api/docs。
- 分页：基于光标的列表端点。
- 过滤：查询与UI过滤选项匹配的参数。

*Webhook（出站）：*
- 每个工作区均可配置。用户可以注册在事件发生时接收 HTTP POST 请求的 Webhook URL。
- 支持的事件：post.created、post.approved、post.scheduled、post.published、post.failed、inbox_message.received、inbox_message.replied、report. generated。
- Webhook 有效负载：JSON，包含事件类型、时间戳和相关资源数据（例如，发布事件的完整发布对象）。
- Webhook 传递：POST 请求，标头中带有 HMAC-SHA256 签名，用于有效负载验证。
- 重试：对非 2xx 响应进行 3 次重试，并进行指数退避。
- Webhook 日志：每个 Webhook 端点最近 100 次传送，显示状态代码、响应时间、有效负载大小。

*扎皮尔/品牌/n8n：*
- REST API 和 webhooks 支持与自动化平台集成。
-（未来）专用 Zapier 触发器和操作作为单独的项目。

**存储集成：**

*谷歌云端硬盘：*
- 将媒体从 Google Drive 导入工作区媒体库。
- 在媒体选择器中，“Google 云端硬盘”选项卡可让用户浏览其云端硬盘并选择文件。
- 需要具有drive.readonly范围的Google OAuth。

*Dropbox：*
- 与 Google Drive 相同，使用 Dropbox Chooser API。
- 无需 OAuth - Dropbox Chooser 小部件处理身份验证。

### 数据模型
- `IntegrationConfig`：id，organization_id，integration_type（枚举：canva，unsplash，pexels，giphy，slack，smtp，google_drive，dropbox），配置（加密的json - API密钥，OAuth令牌， SMTP 设置）、is_active（布尔值）、created_at、updated_at。
- `AIProviderConfig`：id、organization_id、provider（枚举：openai、anthropic、openrouter）、api_key（加密）、default_model（字符串）、is_active（布尔值）、created_at、updated_at。
- `AIDefaultProvider`：id、organization_id、ai_provider_config_id（FK - 指向调用 AI 功能时默认使用的提供者/模型）。
- `SlackWorkspaceConfig`：id、workspace_id、slack_team_id、slack_channel_id、slack_channel_name、webhook_url、events（已启用事件类型的 json 数组）、oauth_token（加密）。
- `APIKey`：id、organization_id、名称、token_hash、范围 (json)、last_used_at、created_at、revoked_at（可为空）。
- `WebhookEndpoint`：id、workspace_id、url、秘密（对于 HMAC）、事件（json 数组）、is_active（布尔值）、created_at。
- `WebhookDelivery`：id、webhook_endpoint_id、event_type、有效负载（json）、response_status_code（整数，可为空）、response_time_ms（整数、可为空）、attempt_number（整数）、delivered_at。

### 依赖关系
- F-2.1（作曲家） - Canva、库存媒体、作曲家中的人工智能。
- F-3.1（收件箱） - 人工智能情绪分析。
- F-7.1（通知）- Slack 通知。
- F-6.1（媒体库）- 来自集成的媒体保存到库中。

### 验收标准
- Canva 按钮打开 Canva 并返回用户会话中的设计（无需重新加载页面）。
- Unsplash 搜索会在 2 秒内返回结果。
- 已发布帖子的 Slack 通知将在发布后 30 秒内到达配置的频道。
- 使用 OpenAI GPT-4o 时，AI 字幕生成会在 5 秒内返回 3 个建议。在 Composer AI 面板中切换到 Anthropic Claude 可以正确地将请求路由到 Anthropic API。切换到 OpenRouter 模型可以通过 OpenRouter 正确路由。
- REST API 对于简单读取端点，在 200 毫秒内响应。
- Webhook 交付包括正确的 HMAC 签名并在失败时重试。

#6.MEDIA MANAGEMENT

## F-6.1 - 媒体库

### 目的
每个工作空间的资产管理系统，用于跨帖子组织、存储和重复使用图像、视频和其他媒体。

### 用户故事
- 作为编辑，我可以上传图像和视频并将它们组织到文件夹中。
- 作为编辑，我可以按名称或标签搜索媒体。
- 作为经理，我可以查看哪些帖子使用特定媒体资产。
- 作为编辑，我可以在不离开平台的情况下编辑图像（裁剪、调整大小）。

### 功能要求

**上传：**
- 拖放上传区域。同时支持多个文件。
- 批量上传：一次最多 50 个文件。
- 支持的格式：JPEG、PNG、WebP、GIF、SVG（图像）； MP4、MOV、AVI、WebM（视频）； PDF（适用于 LinkedIn 文档）。
- 文件大小限制：每个图像最大 20MB，每个视频最大 1GB。
- 每个文件上传进度指示器。
- 上传时，系统自动生成：缩略图（图像和视频）、元数据（尺寸、持续时间、文件大小、格式）。

**组织：**
- 文件夹：创建、重命名、删除、嵌套（最多 3 层）。在文件夹之间拖放文件。
- 标签：任何资产上的自由格式标签。每个资产有多个标签。根据工作区中的现有标签自动完成标签。
- 加星标资产：标记重要资产以便快速访问（过滤视图）。

**搜索和过滤：**
- 跨文件名和标签的全文搜索。
- 过滤依据：文件类型（图像、视频、文档、GIF）、文件夹、上传日期范围、上传者、加星标状态。
- 排序依据：名称、上传日期、文件大小。

**媒体详细信息视图：**
- 单击资产会打开一个详细信息面板，其中显示：完整预览（图像按显示尺寸渲染；视频内嵌播放）、元数据（尺寸、文件大小、格式、持续时间、上传日期、上传者）、标签（可编辑）、用法（引用该资产的帖子列表 - 指向这些帖子的链接）。
- 编辑功能：
  - 图像：裁剪、调整大小、旋转、翻转。编辑创建新版本；原件被保留。
  - 视频：修剪（设置开始和结束时间）。 Trim 创建一个新版本。
- 下载原始文件。
- 删除资产：如果任何计划的（尚未发布）帖子引用该资产，则会阻止删除资产。警告显示哪些帖子引用了它。对于已发布的帖子，允许删除（已发布的内容不受影响）。

**版本历史：**
- 每次编辑都会创建资产的新版本。
- 版本历史记录面板显示：版本号、创建日期、更改说明（例如“裁剪为 4:5”）、缩略图。
- 用户可以恢复以前的版本（使其成为当前版本）。

**共享组织库：**
- 除了工作区范围的库之外，还存在一个组织范围的“共享库”，用于跨工作区使用的品牌资产（徽标、字体、模板）。
- 只有组织管理员可以上传到共享库。
- 所有工作区成员都可以浏览和使用编辑器中共享库中的资源。
- 共享资源在工作区上下文中是只读的（无法在工作区中编辑或删除）。

**平台兼容性警告：**
- 为帖子选择媒体时，如果资产不符合目标平台的要求，库会显示警告（请参阅 F-2.1 媒体验证）。
- 警告在资产缩略图上显示为徽章：黄色（警告 - 可以工作但不是最佳），红色（错误 - 将失败或被平台拒绝）。

**空状态：**
- 当媒体库没有资源时：
  - 插图：带有上传箭头的图像/视频图标。
  - 标题：“尚未上传媒体。”
  - 正文：“上传图像和视频以在您的帖子中进行整理和重复使用。”
  - 主要 CTA：一个大型拖放区域，其中包含“将文件拖放到此处或单击上传”。
  - 辅助文本链接：“或从 Google Drive / Dropbox 导入”（如果配置了集成）。
- 当搜索/过滤器没有产生结果时：“没有媒体与您的搜索匹配。”带有“清除搜索”按钮。

### 数据模型
- `MediaAsset`：id、workspace_id（可为空 - 共享组织库为空）、organization_id、文件名、original_filename、file_url（存储路径）、thumbnail_url、file_type（枚举：图像、视频、gif、文档）、mime_type、file_size_bytes（整数）、宽度（整数、可为空）、高度（整数、可空）、duration_seconds（十进制、可空）、folder_id（可空）、tags（json 数组）、is_starred（布尔值）、uploaded_by（user_id）、current_version_id、created_at、updated_at。
- `MediaAssetVersion`：id、media_asset_id、version_number（整数）、file_url、thumbnail_url、change_description（字符串）、file_size_bytes、宽度、高度、duration_seconds（可为空）、created_by、created_at。
- `MediaFolder`：id、workspace_id、parent_folder_id（可为空）、名称、created_at、updated_at。

### 依赖关系
- F-2.1 (Composer) - 作曲家中的媒体选择器。
- F-5.3（集成）- Canva、库存媒体、Google Drive、Dropbox 导入。
- F-2.4（发布引擎）- 发布前的媒体处理。

### 验收标准
- 上传 10 张图像在 15 秒内完成，并生成所有缩略图。
- 按标签搜索 1,000 个资产，1 秒内返回结果。
- 尝试删除计划帖子引用的媒体资产会被阻止，并显示一条列出受影响帖子的明确消息。
- 图像裁剪工具可在 3 秒内生成 5MB 图像的裁剪版本。
- 共享库资源在所有工作区中可见，但无法从工作区上下文中编辑或删除。

#7.NOTIFICATION SYSTEM

---

## F-7.1 - 通知系统

### 目的
集中式通知引擎为平台上的所有警报和消息提供支持。每个系统（发布、批准、收件箱、分析、调度）都会发出事件，通知系统将这些事件路由到正确的渠道。

### 用户故事
- 作为编辑，当我的帖子被批准或拒绝时，我会收到应用内通知。
- 作为经理，当帖子发布失败时，我会收到一条 Slack 消息。
- 作为客户，当帖子可供我审核时，我会收到一封电子邮件。
- 作为用户，我可以配置我接收哪些通知以及在哪些渠道上接收。

### 功能要求

**通知渠道：**

| 频道 | 详细信息 |
|---------|--------|
| 应用内 | 顶部导航栏中的响铃图标，带有未读计数徽章。单击可打开一个通知抽屉，其中显示最近的通知。单击或用户单击“全部标记为已读”时，通知将标记为已读。 |
| 邮箱 | 发送至用户注册邮箱。如果已配置，则使用组织的白标品牌。批处理：如果 5 分钟内发生多个事件，它们将被批处理到一封电子邮件中（可配置延迟）。 |
| Slack | 发送到工作区配置的 Slack 通道 (F-5.3)。每个事件一条消息（无批处理）。 |
| Webhook | 发送到已注册的 Webhook 端点 (F-5.3)。每个活动一次交付。 |

**事件和默认频道：**

| 事件 | 默认：应用内 | 默认：电子邮件 | 默认：Slack |
|-------|-----------------|----------------|----------------|
| 帖子已提交审批 | 审阅者：是 | 审阅者：是 | 是 |
| 帖子已批准 | 作者：是 | 作者：否 | 是 |
| 请求更改帖子 | 作者：是 | 作者：是 | 是 |
| 帖子被拒绝 | 作者：是 | 作者：是 | 是 |
| 帖子已发布 | 作者：是 | 作者：否 | 是 |
| 发帖失败 | 作者：是 | 作者：是 | 是 |
| 新收件箱消息 | 已分配：是，未分配：工作区管理员 | 否 | 可配置 |
| 收件箱 SLA 逾期 | 已分配：是，经理：是 | 经理：是 8800000000000004888 是|
| 请求客户批准 | 客户：否（单独的魔术链接电子邮件） | 客户：是（魔术链接） | 否|
| 团队成员已邀请 | 受邀者：不适用 | 受邀者：是（邀请电子邮件） | 否 |
| 社交帐户已断开连接 | 工作区管理员：是 | 工作区管理员：是 | 是 |
| 生成的报告 | 已配置的收件人 | 已配置的收件人：是 | 否 |
| 参与警报 | 组织管理员：是 | 组织管理员：是 | 可配置 |

**用户偏好：**
- 每个用户都可以从帐户设置中配置他们的通知首选项。
- 每个事件类型，每个通道：开/关切换。
- “安静时间”设置：在指定时间（时区感知）抑制非关键通知。
- 电子邮件的“摘要模式”：接收总结过去 24 小时内所有通知的每日摘要，而不是单独的电子邮件。

**应用内通知抽屉：**
- 显示 50 个最新通知，按日期排序（最新的在前）。
- 每个通知显示：图标（基于事件类型）、标题（例如“帖子已批准”）、正文（例如“您的帖子‘新产品发布’已得到[经理姓名]批准”）、时间戳、已读/未读指示器。
- 单击通知可导航至相关上下文（例如，单击“帖子已批准”通知可导航至日历上的该帖子）。
- 底部的“查看所有通知”链接可打开全页通知历史记录（分页，可按事件类型和阅读状态进行过滤）。

**通知发送：**
- 通知由后台工作人员异步生成（不在请求路径中）。
- 目标传递时间：触发事件后 30 秒内。
- 电子邮件传送：通过配置的 SMTP（自托管）或托管电子邮件服务（云）。
- Slack 交付：通过 Slack webhook 或 API。
- 失败的交付最多可重试 3 次，并采用指数退避。永久失败的传送会被记录下来，但不会进一步重试。

### 数据模型
- `Notification`：id、user_id（收件人）、event_type（枚举）、标题、正文、数据（json - 上下文数据，如 post_id、workspace_id）、is_read（布尔值）、read_at（日期时间、可为空）、created_at。
- `NotificationPreference`：id、user_id、event_type、频道（枚举：in_app、电子邮件、slack）、is_enabled（布尔值）。
- `NotificationDelivery`：id、notification_id、通道、状态（枚举：待处理、已交付、失败）、error_message（可为空）、delivered_at（可为空）、尝试（整数）。

### 依赖关系
- 所有功能都会发出该系统消耗的事件。
- F-5.2（白标）- 电子邮件品牌。
- F-5.3（集成 - Slack） - Slack 交付。

### 验收标准
- 应用内通知会在触发事件后 5 秒内出现（通过 WebSocket 或轮询）。
- 电子邮件通知将在事件发生后 60 秒内发送（不包括电子邮件提供商的延迟）。
- 禁用“发布后”事件电子邮件的用户不会收到该事件的电子邮件，但如果启用，仍会收到应用内通知。
- 安静时间可以在指定窗口内正确抑制通知。
- 通知抽屉正确显示未读计数并将通知标记为单击时已读。

## F-8.1 - 全局搜索

### 目的
提供快速、工作区范围的搜索，让用户可以查找帖子、草稿、模板、媒体和收件箱消息，而无需手动浏览日历、库或源。随着工作空间在几个月内积累了数百个帖子，搜索对于日常运营变得至关重要。

### 用户故事
- 作为编辑，我可以通过输入部分标题来搜索 3 个月前创建的帖子。
- 作为经理，我可以找到标有特定活动名称的所有帖子。
- 作为编辑，我可以通过文件名或标签在我的媒体库中搜索特定图像。
- 作为经理，我可以通过搜索发件人的姓名或消息内容来找到特定的收件箱对话。

### 功能要求

**搜索界面：**
- 搜索栏始终在顶部导航栏中可见（键盘快捷键：Cmd/Ctrl+K 聚焦）。
- 键入内容会打开一个搜索下拉列表，其中显示按类型分组的结果：帖子、媒体、收件箱消息、模板。
- 每个结果显示：类型图标、标题/说明文字片段（突出显示的匹配项）、日期、状态。
- 单击结果导航到相关项目（日历/详细视图中的帖子、库中的媒体、收件箱中的收件箱消息、编辑器中的模板）。
- 搜索范围仅限于当前工作区。组织管理员可以通过切换按钮在所有工作区中进行搜索。

**搜索范围：**

| 内容类型 | 可搜索字段 |
|-------------|-------------------|
| 帖子 | 标题文本、第一条评论、内部注释、标签、内容类别名称、作者姓名 |
| 媒体 | 文件名、标签 |
| 收件箱消息 | 消息正文、发件人姓名、发件人句柄、内部注释 |
| 模板 | 模板名称、标题文本 |

**搜索行为：**
- 使用 PostgreSQL 内置的 `tsvector`/`tsquery` 进行全文搜索（启动时无需外部搜索引擎）。
- 结果按相关性排名（PostgreSQL `ts_rank`），并按新近程度进行二次排序。
- 最小查询长度：2 个字符。
- 搜索去抖：用户停止输入后 300 毫秒。
- 分页：下拉列表中每种类型的前 5 个结果。每种类型的“查看所有 [N] 个结果”链接可打开带分页的全页搜索结果视图（每页 20 个）。

**整页搜索结果：**
- 可从下拉菜单（“查看所有结果”）或按搜索栏中的 Enter 进行访问。
- 过滤器：内容类型（复选框）、日期范围、状态（帖子）、作者。
- 排序：按相关性（默认）或按日期。

**空状态：**
- 无结果：“‘[查询]’没有结果。尝试不同的关键字或检查您的过滤器。”
- 尚无查询：“搜索帖子、媒体、收件箱消息和模板。”

### 数据模型
- 没有新桌子。搜索在现有表上使用 PostgreSQL 全文搜索索引：
  - `Post`：标题、first_comment、标签的`tsvector`的GIN索引。
  - `MediaAsset`：GIN 文件名、标签的索引 `tsvector`。
  - `InboxMessage`：body、sender_name、sender_handle 的 `tsvector` 上的 GIN 索引。
  - `PostTemplate`：名称 `tsvector` 上的 GIN 索引，caption_text。

### 依赖关系
- F-2.1（作曲家）- 帖子和模板。
- F-3.1（收件箱）- 收件箱消息。
- F-6.1（媒体库）- 媒体资产。

### 验收标准
- 对于包含 5,000 个帖子的工作区，搜索会在 500 毫秒内返回结果。
- 输入“产品发布”会显示包含该短语的所有帖子，并按相关性排名。
- 跨工作空间搜索（组织管理员）可以正确返回带有工作空间名称标签的多个工作空间的结果。
- 键盘快捷键 Cmd/Ctrl+K 聚焦工作区中任何页面的搜索栏。

## F-8.2 - 帖子详细信息视图

### 目的
为已发布或已完成的帖子提供专用的只读视图，将所有相关信息聚合到一个位置：帖子内容、特定于平台的版本、发布日志、分析、批准历史记录和评论。日历和列表视图链接到已发布帖子的详细信息视图，而不是重新打开编辑器。

### 用户故事
- 作为一名经理，我可以单击日历上已发布的帖子，并在一个视图中查看其完整详细信息 - 内容、分析、发布历史记录和团队评论。
- 作为客户，我可以查看已发布帖子的绩效指标及其内容。
- 作为编辑，我可以查看帖子的批准历史记录和版本时间表。

### 功能要求

**导航：**
- 单击日历 (F-2.3)、列表视图或搜索结果中已发布的帖子可打开帖子详细信息视图。
- 单击草稿、待处理或计划的帖子仍会打开作曲家 (F-2.1) 进行编辑。
- 帖子详细信息视图有一个“编辑”按钮（仅对可编辑的帖子可见 - 草稿/计划）。对于已发布的帖子，“编辑”是隐藏的；相反，“复制为草稿”按钮允许创建副本以供修订。

**布局：**
- 带有左侧内容区域和右侧边栏的全页视图。

*左侧内容区：*
- **帖子内容：** 规范的标题文本、媒体（内嵌显示的图像/视频）、第一条评论文本、标签、内容类别。
- **平台版本：** 如果存在特定于平台的覆盖，选项卡式界面将显示每个平台的版本（例如“Instagram”、“LinkedIn”、“Facebook”）以及特定于平台的标题和媒体。 “通用”选项卡显示共享的基础版本。
- **发布日志：** 显示每个平台发布状态的时间线：平台图标、发布时间戳（或失败原因）、平台帖子 URL（可点击链接到平台上的实时帖子）。

*右侧边栏：*
- **状态徽章：**当前帖子状态（已发布、部分发布、失败、已计划等）。
- **元数据：** 作者、创建日期、计划日期、发布日期。
- **分析摘要（针对已发布的帖子）：** 从 F-4.1 中提取的关键指标 - 印象数、覆盖面、参与度、参与率。按平台细分。 “查看完整分析”链接可导航到筛选到此帖子的每个帐户分析仪表板。
- **批准历史记录：** 批准操作（提交、批准、请求更改等）的时间表，涉及人员、时间和任何评论。
- **内部评论：** 团队评论主题（来自 F-2.2 PostComment）。能够从详细视图添加新评论。

**空状态：**
- 最近发布的帖子的分析部分（尚未收集数据）：“分析数据将在发布后 1 小时内提供。”
- 跳过批准的帖子的批准历史记录（工作流程设置为“无”）：“此帖子是在没有批准工作流程的情况下发布的。”

### 数据模型
- 没有新桌子。此视图聚合来自现有模型的数据：Post、PlatformPost、PublishLog、AnalyticsSnapshot、ApprovalAction、PostComment、PostVersion。

### 依赖关系
- F-2.1 (Composer) - 发布数据、平台版本。
- F-2.2（审批工作流程）- 审批历史记录。
- F-2.3（日历）- 从日历到详细视图的导航。
- F-2.4（发布引擎）- 发布日志。
- F-4.1（分析）- 每个帖子指标。

### 验收标准
- 对于发布到 5 个平台的帖子以及 30 天的分析数据，帖子详细视图可在 2 秒内加载。
- 单击日历上已发布的帖子将打开详细信息视图（而不是作曲家）。
- 单击日历上的草稿/预定帖子将打开编辑器（而不是详细视图）。
- “复制为草稿”创建状态为“草稿”的精确副本，并在编辑器中将其打开。
- 发布日志中的平台帖子 URL 正确链接到每个平台上的实时帖子。

## F-8.3 - 发布垃圾邮件和软删除

### 目的
通过实施带有可恢复垃圾的软删除机制，防止意外永久删除帖子。删除的帖子将移至垃圾箱，并可以在保留期内恢复。

### 用户故事
- 作为编辑，如果我不小心删除了帖子，我可以从垃圾箱中将其恢复。
- 作为经理，我可以查看所有最近删除的帖子并恢复它们。
- 作为组织管理员，我可以配置已删除的帖子在永久删除之前保留多长时间。

### 功能要求

**软删除：**
- 当用户删除帖子（从日历、列表视图或编辑器）时，该帖子不会永久删除。相反，它被移至垃圾箱（状态设置为 `trashed`，记录了 `trashed_at` 时间戳）。
- 该帖子将从日历、列表视图、队列和搜索结果中消失。
- 删除前的确认对话框：“该帖子将被移至垃圾箱。您可以在 [N] 天内恢复它。”该对话框显示帖子标题片段和平台。

**垃圾箱视图：**
- 可从工作区侧边栏访问：“垃圾箱”链接（带有垃圾帖子计数徽章）。
- 显示已删除帖子的列表：标题片段、平台、原始状态（删除前）、删除者、删除日期、永久删除前剩余天数。
- 每个帖子的操作：“恢复”（将帖子返回到之前的状态）、“永久删除”（需要管理员+角色，带有第二个确认对话框：“此操作无法撤消”）。
- 批量操作：“恢复所选内容”、“永久删除所选内容”。
- 排序：按删除日期（最新的在前，默认）。

**保留：**
- 默认保留期：30 天（可通过 F-1.6 工作区设置进行配置 - 添加 `trash_retention_days`，最小值 7，最大值 90）。
- 每日后台作业会永久删除 `trashed_at + retention_days < now()` 的帖子。
- 永久删除的帖子及其关联的 PlatformPost 记录、PostVersions、PostMedia 引用（媒体资产本身 NOT 被删除 - 仅引用）、ApprovalActions 和 PostComments 将从数据库中删除。

**恢复行为：**
- 恢复帖子会将其恢复到删除前的状态。如果帖子是“已安排”的，并且安排的时间现在已经过去，则状态将更改为“草稿”。
- 恢复帖子会将其按原始日期/时间放回到日历上（如果时间已过，则作为草稿）。
- 恢复的帖子保留所有版本历史记录、批准历史记录和评论。

**RBAC：**
- 任何可以删除帖子的用户（自己的帖子为编辑+，其他人的帖子为经理+）都可以将其发送到垃圾箱。
- 查看垃圾箱：编辑器+（查看自己的垃圾帖子）、经理+（查看工作区中所有垃圾帖子）。
- 恢复：与删除相同的权限。
- 永久删除：仅限 Manager+。

### 数据模型
- 扩展 `Post` 表：添加 `trashed_at`（日期时间，可为空）、`trashed_by`（user_id，可为空）、`pre_trash_status`（枚举，可为空 - 存储帖子发布之前的状态被扔掉了）。
- 将状态值 `trashed` 添加到 Post status 枚举。

### 依赖关系
- F-2.1（作曲家）- 删除作曲家中的操作。
- F-2.3（日历）- 删除日历上的操作，侧边栏中的垃圾视图。
- F-1.3 (RBAC) - 垃圾操作的权限检查。
- F-1.6（可配置默认值） - `trash_retention_days` 设置。

### 验收标准
- 删除帖子会将其移至垃圾箱并立即从日历中删除。
- 恢复已删除的帖子会将其返回到日历，并且其原始内容和元数据完好无损。
- 31 天前删除的帖子（默认保留 30 天）将被后台作业永久删除。
- 垃圾箱视图正确显示永久删除前的剩余天数。
- 永久删除的帖子无法恢复。

## F-8.4 - 数据导出（GDPR 合规性）

### 目的
允许组织所有者以结构化、可移植的格式导出与其组织或特定工作区相关的所有数据。支持GDPR数据迁移需求，为用户提供平台迁移路径。

### 用户故事
- 作为组织所有者，我可以将组织的所有数据导出为可下载的存档。
- 作为经理，我可以导出单个工作区的数据以供客户交接。
- 作为组织所有者，我可以请求删除我的组织的所有数据。

### 功能要求

**出口范围：**
- 两个导出级别：组织范围或单个工作区。
- 组织导出：包括所有工作区、成员、设置和共享库。
- 工作区导出：仅包括该工作区范围内的数据。

**导出内容：**

| 数据类型 | 格式 | 包含在 | 中
|-----------|--------|-------------|
| 帖子（所有状态，包括已删除） | JSON + CSV | 工作区、组织|
| 发布媒体文件（图像、视频） | `media/` 目录中的原始文件 | 工作空间、组织 |
| 平台帖子元数据（发布日志、平台帖子 ID） | JSON | 工作空间、组织 |
| 分析快照 | CSV（每个帐户一个文件） | 工作区、组织 |
| 收件箱消息和回复 | JSON | 工作空间、组织 |
| 内部注释 | JSON | 工作空间、组织 |
| 已保存的回复 | JSON | 工作空间、组织 |
| 报告配置 | JSON | 工作区、组织 |
| 生成的 PDF 报告 | PDF 目录中的 `reports/` 个文件 | 工作区、组织|
| 媒体库（所有资源 + 文件夹结构） | `media/` 目录中的原始文件 + `media_index.json` | 工作区、组织|
| 内容类别和标签 | JSON | 工作空间、组织 |
| 团队成员和角色 | JSON（电子邮件、姓名、角色 - 无密码） | 工作空间、组织 |
| 审批历史记录 | JSON | 工作空间、组织 |
| 组织设置 | JSON | 仅组织 |
| 白标签配置 | JSON + 徽标/图标文件 | 仅组织 |
| 审核日志 | CSV | 仅组织 |

**出口流程：**
- 从以下位置触发：组织设置→数据管理→“导出数据”（组织范围）或工作区设置→“导出工作区数据”。
- 只有组织所有者才能触发组织范围内的导出。 Managers+ 可以触发工作区导出。
- 点击“导出”后，系统显示：“您的导出正在准备。准备好后，您将收到一封包含下载链接的电子邮件。大量导出可能需要长达 1 小时。”
- 导出作为后台作业运行。进度不会实时显示（即发即忘，完成后会收到电子邮件通知）。
- 导出打包为 `.zip` 文件，其中包含 JSON、CSV 以及按目录组织的媒体文件。
- 下载链接通过电子邮件发送给请求用户。该链接将在 7 天后过期。
- 下载链接也可在组织设置→数据管理→“最近导出”（包含下载链接和到期日期的过去导出列表）中找到。

**出口 ZIP 结构：**
```
export-[org-slug]-[date]/
├── manifest.json          # Export metadata: date, scope, version
├── organization.json      # Org settings, members, roles
├── workspaces/
│   ├── [workspace-slug]/
│   │   ├── posts.json
│   │   ├── posts.csv
│   │   ├── analytics/
│   │   │   ├── [account-name].csv
│   │   ├── inbox_messages.json
│   │   ├── media/
│   │   │   ├── [original files]
│   │   │   └── media_index.json
│   │   ├── reports/
│   │   │   ├── [generated PDFs]
│   │   └── settings.json
├── shared_media/
│   ├── [shared library files]
│   └── media_index.json
├── whitelabel/
│   ├── config.json
│   ├── logo.png
│   └── favicon.ico
└── audit_log.csv
```

**数据删除：**
- 组织设置→数据管理→“删除所有数据”。
- 只有组织所有者才能触发删除。
- 删除遵循与组织删除相同的宽限期流程 (F-1.1)：30 天宽限期，包含电子邮件确认、倒计时和取消选项。
- 宽限期过后，所有数据将被永久删除：数据库记录、媒体文件、生成的报告、审核日志。
- 删除记录在单独的、不可变的系统日志中（不是组织自己的审核日志，它本身会被删除）。

### 数据模型
- `DataExport`：id，organization_id，workspace_id（可为空 - 组织范围为空），requested_by（用户id），状态（枚举：待处理，处理，已完成，失败），file_url（字符串，可为空），file_size_bytes（整数，可为空），expires_at（日期时间，可为空），error_message（可为空），created_at， Completed_at（可为空）。

### 依赖关系
- F-1.1（组织）- 组织范围内的导出和删除。
- F-1.2（工作空间）- 工作空间范围内的导出。
- F-7.1（通知）- 带有下载链接的电子邮件。

### 验收标准
- 导出包含 1,000 个帖子和 500 个媒体资产的工作区可在 30 分钟内完成。
- 导出的 ZIP 结构良好，所有 JSON 文件都是有效的 JSON。
- 导出中的媒体文件与原始文件匹配（逐字节）。
- 下载链接正确地在 7 天后过期并返回 410 Gone 响应。
- 宽限期后的数据删除将删除所有记录 - 对组织 ID 的查询在所有表中返回零行。

## F-8.5 - 时区处理

### 目的
定义如何在平台上存储、显示和转换日期和时间。社交媒体调度本质上是对时区敏感的 - 纽约的机构为东京的客户调度帖子必须对帖子的发布时间充满信心。

### 功能要求

**存储：**
- 数据库中的所有时间戳都存储在UTC中。没有例外。
- 时区信息存储在三个级别：组织（新工作区的默认时区）、工作区（用于调度和显示的主时区）、用户（用于通知和显示的用户个人时区）。

**显示规则：**

| 上下文 | 使用的时区 | 显示格式 |
|---------|--------------|----------------|
| 日历（工作区） | 工作区时区 | "Mar 15, 2:30 PM EST" - 始终显示时区缩写|
| 帖子编辑器：日程选择器 | 工作区时区（默认），带有用于切换到用户时区的下拉菜单 | 显示工作区时间和用户时区中的等效时间（如果它们不同） |
| 帖子详细信息视图：发布时间戳 | 工作空间时区 | 与日历相同 |
| 收件箱：消息收到时间戳 | 工作区时区 | 相对（“2 小时前”），悬停时具有完整时间戳 |
| 分析：日期范围选择器 | 工作区时区 | 仅日期（无时间部分） |
| 通知（应用内） | 用户时区 | 相对（“5 分钟前”），悬停时带有完整时间戳 |
| 通知电子邮件 | 用户的时区 | 完整日期 + 时间（带时区缩写） |
| 报告 (PDF) | 工作区时区 | 显式：“所有时间均以东部标准时间显示(UTC-5)" 位于报表标题 |
| 审核日志 | UTC | ISO 8601 格式（带 Z 后缀） |
| REST API（所有端点） | UTC | ISO 8601 格式，带 Z 后缀 |

**时区选择：**
- 组织默认时区：在组织设置 → 常规中设置。按地区分组的所有 IANA 个时区的下拉列表。默认值：注册期间从组织所有者的浏览器检测到。
- 工作区时区：在“工作区设置”→“常规”中设置。默认为组织的时区。可以按工作区覆盖（例如，对于不同时区的客户端）。
- 用户时区：在帐户设置 → 首选项中设置。首次登录时从浏览器自动检测。可以手动覆盖。

**日程安排清晰度：**
- 在后期编辑器的日程选择器中，当用户的时区与工作区时区不同时，选择器会显示双时间：
  - 主要：“3 月 15 日下午 2:30 EST 的计划”（工作空间时区）。
  - 次要：“（您的时间上午 9:30，PST）”（用户的时区）。
- 这可确保为东京客户安排的纽约用户清楚地看到这两个时间。

**夏令时（DST）：**
- 该平台使用IANA时区数据库（通过`pytz`或Python的`zoneinfo`）自动处理DST转换。
- 当帖子安排的时间落入 DST 间隙（例如，春天的凌晨 2:30）时，系统会将帖子转移到下一个有效时间并通知用户：“由于夏令时更改，安排的时间已调整。”
- 当帖子被安排在 DST 重叠（回退）中的时间时，系统将使用第一次出现的时间（回退前时间）。

### 数据模型
- 没有新桌子。时区字段已存在于组织 (`default_timezone`)、工作区 (`timezone`) 和用户 (`timezone`) 上。
- 所有现有的 `datetime` 列都使用 `DateTimeField` （存储 UTC）。显示转换发生在视图/模板层，而不是数据库层。

### 依赖关系
- F-1.1（组织）- 组织时区设置。
- F-1.2（工作空间）- 工作空间时区设置。
- F-2.1 (Composer) - 调度程序中的双时区显示。
- F-2.3（日历）- 时区感知日期显示。
- F-2.4（发布引擎）- 在正确的 UTC 时间发布。

### 验收标准
- PST 中的用户计划在上午 9:00 EST（工作区时区）发帖，在作曲家。
- 该帖子发布时间为 14:00 UTC (9:00 AM EST)。
- 日历视图显示工作区时区中的所有帖子，无论查看用户的个人时区如何。
- 计划在春季 DST 日凌晨 2:30 发布的帖子会自动转移到凌晨 3:00，并通知用户。
- REST API 始终以 ISO 8601 格式返回 UTC 时间戳。

## F-8.6 - 链接缩短和 UTM 跟踪

### 目的
机构需要跟踪链路性能以向客户证明 ROI。此功能提供 UTM 参数管理（用于 Google Analytics 中的活动归因）和可选的链接缩短，以实现更清晰的社交帖子。

### 用户故事
- 作为经理，我可以为工作区设置默认的 UTM 参数，以便每个帖子自动包含跟踪。
- 作为编辑，我可以为每个帖子自定义 UTM 个参数。
- 作为经理，我可以为我的帖子生成缩短的链接。

### 功能要求

**UTM 参数管理：**

*工作区级别默认值（在“工作区设置”→“链接跟踪”中配置）：*
- 默认 UTM 参数应用于此工作区帖子中的所有链接：

| 参数 | 默认模板 | 每个帖子可编辑 |
|-----------|-----------------|-------------------|
| `utm_source` | `{platform}`（自动替换：instagram、facebook、linkedin 等） | 是|
| `utm_medium` | `social` | 是 |
| `utm_campaign` | `{workspace_slug}` | 是 |
| `utm_content` | `{post_id}` | 是 |
| `utm_term` |（空） | 是 |

- 模板变量：`{platform}`、`{workspace_slug}`、`{post_id}`、`{category}`、`{date}` （计划发布的 YYYY-MM-DD）。
- 切换：“自动将 UTM 参数附加到帖子中的所有链接”（默认值：关闭）。启用后，帖子标题中的任何 URL 都会在发布时自动附加 UTM 个参数。

*每个帖子覆盖：*
- 在后期编辑器 (F-2.1) 中，“链接跟踪”面板（可折叠）显示将应用的 UTM 参数。
- 用户可以编辑该特定帖子的任何参数。
- 预览：只读字段显示完整的 URL 和 UTM 参数，正如发布后显示的那样。

**链接缩短：**

*内置缩短器：*
- 发布时不包含在内。链接缩短仅限外部使用（见下文）。未来版本中可能会添加内置缩短器。

*外部缩短器集成：*
- 工作区设置→链接跟踪→“链接缩短器”部分。
- 支持的服务：Bitly、Short.io。每个都需要在工作区级别配置的 API 密钥。
- 配置并启用缩短器后，帖子中的链接会在发布时缩短（附加 UTM 个参数后）。
- 原始长 URL（带有 UTM）存储在 Post 记录中。缩短的 URL 在已发布的标题中替换了它。
- 如果缩短 API 失败，则帖子将以完整（未缩短的）URL 发布，并记录警告。

**分析中的链接跟踪：**
- UTM 标记的链接由客户自己的 Google Analytics（或同等工具）跟踪。该平台不提供自己的点击跟踪 - 它依赖于目标分析获取的 UTM 参数。
- 在帖子详细信息视图 (F-8.2) 中，“链接”部分显示：原始 URL、应用的 UTM 参数、缩短的 URL（如果适用）。

### 数据模型
- `WorkspaceLinkSettings`：id、workspace_id、auto_append_utm（布尔值）、default_utm_source（字符串）、default_utm_medium（字符串）、default_utm_campaign（字符串）、default_utm_content（字符串）、default_utm_term（字符串）、shorter_provider（枚举：none、bitly、short_io、可为空）， Shorter_api_key（加密，可为空）、created_at、updated_at。
- 扩展 `Post`：添加 `link_utm_overrides`（json，可为空 - 每个帖子 UTM 覆盖）。
- 扩展 `PlatformPost`：添加 `shortened_urls`（json，可为 null - 原始 URL 的映射→缩短为该平台发布版本的 URL）。

### 依赖关系
- F-2.1（作曲家） - UTM 作曲家面板。
- F-2.4（发布引擎）- 附加 UTM 并在发布时缩短。
- F-1.6（可配置默认值）- 工作区级别 UTM 默认值。
- F-8.2（帖子详细信息视图）- 链接跟踪显示。

### 验收标准
- 启用 auto-UTM 且链接 `https://example.com/sale` 的帖子发布了 `https://example.com/sale?utm_source=instagram&utm_medium=social&utm_campaign=client-a&utm_content=123`。
- 每个帖子 UTM 覆盖正确替换工作区默认值。
- 配置的 Bitly 集成缩短了 8800000000000000888 标记的 88000000000001888，并且缩短的链接出现在已发布的帖子中。
- 如果 Bitly API 失败，该帖子仍会使用完整的 URL 进行发布，并记录错误。
- 模板变量（`{platform}`、`{post_id}` 等）在发布时正确解析。

## F-8.7 - 内容类别管理

### 目的
内容类别在整个平台中引用 - 在编辑器、日历、队列、分析和报告中 - 但需要专用的管理界面来创建、编辑和组织它们。

### 用户故事
- 作为经理，我可以为我的工作区创建内容类别（例如“教育”、“促销”、“幕后”）。
- 作为经理，我可以为类别分配颜色，以便在日历上进行视觉区分。
- 作为编辑，我可以为任何帖子分配类别。
- 作为经理，我可以看到按类别细分的分析。

### 功能要求

**类别 CRUD（工作区设置 → 内容类别）：**
- **创建：** 名称（必需，每个工作区唯一，最多 50 个字符）、颜色（从 12 种预定义颜色的调色板中选择十六进制选择器，或自定义十六进制输入）、描述（可选，最多 200 个字符）。
- **编辑：** 更新名称、颜色或描述。更改会反映在引用类别的所有位置（日历、分析、报告），而无需重新标记帖子。
- **重新排序：** 拖放以设置显示顺序。顺序决定下拉列表和日历图例中的排序。
- **删除：** 仅当当前没有帖子分配给某个类别时才能删除该类别。如果帖子引用了该类别，则用户必须首先将这些帖子重新分配给其他类别或“未分类”。显示受影响帖子的计数：“此类别已被 [N] 个帖子使用。删除前重新分配它们。”
- **默认类别：** 创建的新工作区没有类别。 “入门集”按钮提供了创建通用集的一键选项：“教育”、“促销”、“幕后”、“用户生成内容”、“季节性/假日”。用户可以跳过此步骤并从头开始创建自己的。

**类别分配：**
- 在后期编辑器 (F-2.1) 中，“类别”下拉列表显示所有工作区类别，按显示顺序排序。
- 一篇文章只能有一个类别（或没有 - 当未选择类别时，“未分类”是隐式默认值）。
- 也可以从日历中分配类别（右键单击帖子→“设置类别”→下拉菜单）。

**日历上的类别颜色：**
- 将类别分配给帖子后，日历上的明信片会显示与类别颜色匹配的彩色左边框或点。
- 日历顶部的图例（可切换）显示所有类别及其颜色。

**类别分析：**
- F-4.1 分析仪表板包括“按类别表现”部分：显示所选日期范围内每个类别的总帖子数、平均参与率、总覆盖率和总印象数的表格或条形图。
- F-4.3 报告生成器包括“内容类别表现”部分类型。

### 数据模型
- `ContentCategory`：id、workspace_id、名称、颜色（十六进制字符串）、描述（可为空）、display_order（整数）、created_by（user_id）、created_at、updated_at。
- Post.category_id 已作为 ContentCategory 的 FK 存在。

### 依赖关系
- F-2.1（作曲家）- 类别下拉列表。
- F-2.3（日历） - 类别颜色显示、图例、右键单击分配。
- F-4.1（分析）- 按类别细分。
- F-4.3（报告）- 类别绩效报告部分。

### 验收标准
- 创建一个具有名称和颜色的类别，立即使其在作曲家和日历中可用。
- 重命名类别会更新所有现有参考（日历、分析），无需重新标记帖子。
- 尝试删除已分配帖子的类别会显示计数并阻止删除。
- 日历正确地将类别颜色显示为明信片上的左边框强调色。
- 分析“按类别表现”图表正确聚合每个​​类别的指标。

#11.TECHNICAL REQUIREMENTS

### 平台集成架构

所有社交平台集成都使用直接的第一方 API。每个平台都有一个专用的提供商模块。

```
Provider Interface (abstract):
  - authenticate(credentials) → OAuth tokens / session
  - refreshToken(tokens) → new tokens
  - publishPost(account, content, media) → PlatformPostResult
  - publishComment(platformPostId, text) → CommentResult
  - getPostMetrics(platformPostId) → Metrics
  - getAccountMetrics(account, dateRange) → AccountMetrics
  - getAudienceDemographics(account) → Demographics
  - getInboxMessages(account, since) → Message[]
  - replyToMessage(messageId, text) → Reply
  - getAccountProfile(tokens) → Profile

Implementations:
  - FacebookProvider (Graph API)
  - InstagramProvider (Instagram Graph API via Facebook)
  - LinkedInProvider (Marketing API v2)
  - TikTokProvider (Content Posting API)
  - YouTubeProvider (Data API v3)
  - PinterestProvider (API v5)
  - ThreadsProvider (Threads API)
  - BlueskyProvider (AT Protocol)
  - GoogleBusinessProvider (GBP API)
  - MastodonProvider (Mastodon API)
```

不使用统一或第三方社交媒体 API 提供商。每个提供商都管理自己的 OAuth 流程、令牌刷新、速率限制和错误处理。

### 后台作业
- **帖子发布者：** 每 15 秒运行一次，获取预定的帖子，发送给提供商。
- **分析收集器：** 每小时收集最近的帖子，每天收集旧帖子和帐户指标，每周收集人口统计数据。
- **收件箱同步器：** 每个帐户每 5 分钟一次（轮询）。支持平台的 Webhook 接收器。
- **令牌刷新：** 每小时检查是否有过期令牌。
- **报告生成器：** 按计划或手动请求触发。
- **媒体处理器：** 处理下一小时内安排的帖子的媒体。
- **重复生成器：**每天，最多提前 90 天为重复规则创建帖子实例。
- **清理：**每天，删除过期的魔法链接、旧的发布日志（90 天）、旧的 webhook 传递日志（30 天）。
- **垃圾清除：**每天，永久删除 `trashed_at + retention_days < now()` (F-8.3) 的帖子。
- **数据导出生成器：** 按需（由用户请求触发），处理工作区或组织导出以及完成时的电子邮件下载链接 (F-8.4)。
- **帐户运行状况检查器：** 每个连接的帐户每 6 小时检查一次。

### 安全
- OAuth 令牌：AES-256-GCM 静态加密。来自环境变量的加密密钥，从未存储在数据库中。
- 工作空间隔离：所有数据库查询都在 WHERE 子句中包含workspace_id。在ORM/查询层强制执行，而不仅仅是应用层。
- API 速率限制：可配置（默认值：每个 API 密钥 1,000 个请求/小时）。
- 登录速率限制：每 15 分钟每封电子邮件 5 次失败尝试 → 临时锁定（15 分钟）。
- CSRF 对所有状态更改端点的保护。
- 审核日志：记录的所有破坏性操作（删除工作区、删除成员、断开帐户、删除帖子）：user_id、操作、目标实体、时间戳、IP 地址。审核日志保留 1 年。
- GDPR 合规性：可通过设置进行数据导出（完整工作区数据为 JSON/CSV zip）和数据删除（工作区或组织级别）。自托管者拥有所有数据。
- 所有页面上的内容安全策略标题。
- 依赖扫描：CI 管道中的自动漏洞扫描。
